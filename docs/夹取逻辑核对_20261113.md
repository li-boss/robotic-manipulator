## 8099 控制台追加修复

用户确认所谓“8090models”指 `http://192.168.137.102:8099/` 识别控制台。
该控制台调用 `pc/vision_service.py`；碰撞拒绝文字由开发板规划器返回，
页面自身不计算关节、桌面碰撞或可达性。

检查的历史日志为 `pc/block_vision/weights/service_err.log` 与
`pc/block_vision/weights/grasp_service/grasp_*.json`。例如2026-11-13 16:18:48有
`POST /api/grasp` 的HTTP 200记录，却没有对应的目标或结果文件。
旧服务对成功及失败都返回HTTP 200，且只有板端受理后才保存结果，
所以无法从这一行还原当次失败目标或认定当次已执行。
历史保存的 `diag_152915` 是普通快照，没有冻结编号和六关节读数，不能冒充本次失败证据。

发现并修复以下可复现缺陷：

1. 原提交只读取进程内最后一次冻结，没有绑定页面所看的结果；新提交核对
   `freeze_id/frame_id/session_id`，其他标签页替换目标后，旧页面会被拒绝。
2. 原重新冻结期间没有清空可提交旧结果；原双击确认也可跨越一次重新冻结。
   现在开始冻结即清空旧结果和确认，失败时不能继续使用旧目标，确认仅绑定本次预览。
3. 原状态轮询可能在提交未完成时重新启用按钮，后端也没有冻结/提交互斥。
   现在前后端均限制并发，并在向板端提交前消耗本次结果；超时后不能重发同一冻结。
4. 原冻结有效期从推理结束后才开始；现在从收到冻结图开始计算，包含推理耗时。
5. 原规划拒绝没有落盘；现在每次冻结保存原图、关节元数据、完整识别结果、像素载荷，
   提交保存原始请求、受理/拒绝/状态未知和原始错误。页面展示证据目录。

上述缺陷不能直接证明是本次约230毫米碰撞拒绝的原因。未改动定位、自校、逆解或碰撞条件。
