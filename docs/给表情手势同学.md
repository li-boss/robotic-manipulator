## 1. 你要做的事（一句话）

写一个**表情/手势识别器类**。它输入一帧摄像头图像，识别到约定的表情或手势时返回 `GestureEvent(label, confidence)`，否则返回 `None`。取帧、防抖、冷却、把标签映射成跳舞动作、通知开发板执行，都已经做好。

最终效果：在网页上开启“表情手势跳舞”模式后，对着摄像头做出约定的表情或手势（例如笑、挥手），机械臂就会跳对应的舞（画圈 / 蛇形）。

## 5. 你要实现的接口

### 5.1 基类（`pc/gesture/base.py`，已存在，不要改）

```python
class GestureRecognizer(ABC):
    @abstractmethod
    def recognize(self, image) -> Optional[GestureEvent]:
        ...

    def close(self):
        """释放模型/资源（可选）。"""
```

- **输入** `image`：一帧 BGR 格式的 `numpy.uint8` 数组，形状 H×W×3。
  - `--source webcam`（默认）：来自电脑摄像头，分辨率由摄像头决定。
  - `--source board`：来自开发板摄像头，640×480，约 5～10 帧/秒，装在机械臂末端，跳舞时会跟着动。
  - `--source none`：键盘模拟，此时 `image` 为 `None`，你的识别器要能处理这种情况。
- **输出**：识别到约定的表情或手势时返回 `GestureEvent(label, confidence)`；否则返回 `None`。
- `recognize()` 只回答“这一帧是什么”，**不用管**防抖、冷却和机械臂。主循环会逐帧调用它，所以要尽量快（建议每帧 < 100 ms）。
- 耗时的初始化（加载模型等）放在 `__init__` 里。`__init__` 不能有必填参数：主循环用 `load_class("模块:类名")` 无参数实例化。需要配置时用默认参数或环境变量。
- 退出时主循环会调用 `close()`，用来释放摄像头以外的资源，比如模型句柄。

### 5.2 输出数据结构（`pc/armlink/types.py`）

```python
@dataclass
class GestureEvent:
    label: str              # 你自己定义的类别名，例如 'smile'、'wave'、'thumbs_up'
    confidence: float = 1.0 # 0～1
```

标签名由你决定，只要和运行时的 `--map` 对得上。建议用小写英文，不要带空格、逗号或等号，并在你的 README 里列出所有标签。

### 5.3 最小示例（新建 `pc/gesture/my_recognizer.py`）

```python
from armlink import GestureEvent
from .base import GestureRecognizer


class MyRecognizer(GestureRecognizer):
    def __init__(self, model_path='pc/gesture/weights/gesture.task', min_conf=0.5):
        self.model = load_model(model_path)     # 只加载一次
        self.min_conf = min_conf

    def recognize(self, image):
        if image is None:                       # --source none 时
            return None
        label, conf = self.model.predict(image) # 你的推理，例如返回 ('smile', 0.92)
        if label is None or conf < self.min_conf:
            return None
        return GestureEvent(label=label, confidence=float(conf))

    def close(self):
        self.model.close()
```

参考实现：[pc/gesture/keyboard.py](../pc/gesture/keyboard.py)。它不用模型：在终端里输入标签名并回车，就算识别到一次。

### 5.4 主循环做了什么（`pc/run_gesture_dance.py`，已写好）

1. `client.wait_for_mode('gesture_dance')`：等待网页开启“表情手势跳舞”模式，拿到 `session_id`、本次授权的动作列表 `routines`、`max_actions` 和 `cooldown_s`。如果 `--map` 里有未授权的动作，会先打印警告。
2. 每一帧：
   1. 从 `source.read()` 取一帧，交给 `recognizer.recognize(image)`。
   2. 交给 `Debouncer`：同一标签连续 `--stable` 帧（默认 3）且 `confidence ≥ --threshold`（默认 0.6），才算触发一次。触发后，要先看到别的结果（或者 `None`），同一标签才能再次触发，所以一直保持同一个手势不会连着跳。
   3. 用 `--map` 把标签换成动作名，再调用 `client.dance(session, routine, label, confidence)`。请求会自动带一个随机的 `request_id`，网络重发也不会跳两次。
   4. `client.wait_job()` 等这一套跳完，再继续识别。开发板还会强制执行网页上设置的“两次之间最短间隔”。
3. 以下情况会结束本次会话，程序随之退出：次数用完、超时、任一动作失败、网页点“关闭模式”，或在电脑端按 Ctrl+C（会请求结束会话；已下发的动作无法撤回，不是急停）。

### 5.5 现有跳舞动作（`board/data/dances.json`）

| 动作名 | 中文 | 内容 | 用时（默认参数） |
|---|---|---|---|
| `circle` | 画圈 | 1 号底座和 4 号腕关节按圆周 8 个点组合运动，末端画一个小圈，±15° | 约 17 秒（含到起始姿态） |
| `snake` | 蛇形 | 1～6 号关节一起按正弦波摆动，相邻关节相位错开 45°，像一条波从底座传到夹爪；1、2 号 ±10°，其余 ±20°，2 圈 | 约 23 秒 |

- 每套动作都先按姿态按钮的顺序逐关节到起始姿态，再逐拍同批下发；运动中不回读角度。
- 起始姿态的限制：`snake` 会让 5 号关节摆 ±20°，而 5 号的范围是 90～250°，所以起始姿态的 5 号要 ≥110°，例如 `90, 90, 90, 90, 130, 90`。网页会把越界或模型碰撞检查不通过的情况直接标出来，并拒绝执行。
- 要加新动作或调整幅度：可以改 `dances.json` 的参数（幅度 1～30°、重复 1～5 次、每拍 500～3000 ms）。新的动作花样需要改 `board/dance.py`，由机械臂控制同学来改。

### 5.6 底层 HTTP 接口（主循环已封装，一般不用手写）

基地址 `http://192.168.137.100:8080`，模拟时为 `http://127.0.0.1:8092`。

| 方法 路径 | 请求 | 响应 | 会不会动 |
|---|---|---|---|
| `GET /api/v1/health` | — | `{service, api_version:1, mode:"real"/"simulation", camera, busy}` | 不动 |
| `GET /api/v1/mode` | — | `{armed, kind, session_id, used, max_actions, expires_in, busy, routines, cooldown_s, message}` | 不动 |
| `GET /api/v1/job` | — | `{busy, job:{id, status, sent, total, message, error}}`，status 为 running / completed / failed / stopped | 不动 |
| `GET /api/v1/frame.jpg` | — | 开发板摄像头最新一帧 JPEG | 不动 |
| `POST /api/v1/gesture` | `{session_id, routine, request_id(32位小写十六进制), label?, confidence?}` | `{job:{id,status,total}, routine, duration_ms, used}`；同一 `request_id` 重发只返回原任务 | **会动**（会话已授权） |
| `POST /api/v1/stop` | `{session_id?}` | 结束会话 | 停止后续动作 |

失败时返回 HTTP 400/503 和 `{"error": "中文原因"}`，`BoardClient` 会把它抛成 `BoardError(message, status)`。

## 9. 常见拒绝原因（开发板返回的中文提示）

| 提示里包含 | 含义 / 怎么办 |
|---|---|
| `模式未开启` / `会话编号不符` | 网页上还没开启，或者已经重开；重新运行主循环即可 |
| `本会话未授权该跳舞动作` | `--map` 里的动作没有在 /modes 页面勾选 |
| `距上一次跳舞不足…秒` | 冷却时间没到；主循环会继续识别，下一次再触发 |
| `次数已用完` | 达到网页上设置的最多次数，会话结束 |
| `越界` / `模型碰撞检查未通过` | 起始姿态不适合这套动作；请机械臂控制同学换起始姿态或减小幅度 |
| `识别模式正在开启中，请先在 /modes 关闭模式` | 模式开着的时候不能用首页按钮跳舞 |

## 10. 测试与交付

- 本地测试（不连硬件）。Mac/Linux：

```bash
zsh tools/run_tests.sh
```

  Windows 只跑电脑端测试：

```powershell
python -m unittest discover -s pc\tests -p "test_*.py"
```

- 给你的识别器写一个小测试，放在 `pc/tests/test_gesture_<名字>.py`：喂几张已知图片（例如笑脸、挥手、空背景），检查返回值是 `GestureEvent` 或 `None`、`confidence` 在 0～1 之间、`label` 在你列出的标签集合里。还要测 `image=None` 不报错。缺少模型文件时用 `unittest.skipUnless` 跳过。
- git：在分支 `feat/gesture` 上开发，只提交 `pc/gesture/`、`pc/tests/` 和你的依赖文件，然后提合并请求，由机械臂控制同学 review。**不要直接推 main**，不要提交大模型文件。
- 交付前检查清单：
  - [ ] 在 `board/simulate.py` 上用键盘模拟和你的识别器都跑通（completed）
  - [ ] `recognize(None)` 返回 `None`，不报错
  - [ ] `__init__` 无必填参数，`--recognizer 模块:类名` 能加载
  - [ ] 标签列表和推荐的 `--map` 写清楚
  - [ ] 依赖已写进 `pc/gesture/requirements.txt`，模型下载方式写清楚
  - [ ] 测试通过，且没有连接真实机械臂
