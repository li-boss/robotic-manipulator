# 方块识别局域网接口（`jjt-detect/1`）

> 给方块识别同学。2026-11 起项目改为：**只有机械臂控制同学的 Mac 连接开发板**；方块识别模型跑在你自己的电脑上，通过局域网收图、回识别结果。你不需要、也不应该再连接开发板或改开发板上的任何文件。

---

## 1. 整体怎么走

```
你的电脑（Windows，局域网）              控制同学的 Mac（唯一连开发板）                  开发板（不变）
                                          pc/run_block_grasp.py --detect-url http://你的IP:8100
                                            ① 请开发板冻结一帧 ───────────────────────────► /api/v1/block/frame
                                            ◄────────────── JPEG 原图 + frame_id + 六关节读数
 检测服务（你的模型）◄── ② POST /detect（JPEG 原图）
                    ── ③ 返回顶面四角/中心/置信度 ──►
                                            ④ 校验后提交像素结果 ──────────────────────────► /api/v1/block/target
                                                                                              定位、逆解、碰撞检查、执行
```

- 什么时候开始由控制同学决定：会话开启后，他在开发板 `/modes` 页面每点一次“开始识别夹取”，Mac 才冻结一帧发给你，一次点击只发一张。你的服务只需一直开着等请求。
- 你只负责“一张图 → 图中方块的像素位置”。冻结、提交、规划、碰撞检查、运动授权全部在控制同学那边，与你无关。
- 你收到的就是开发板冻结的那一帧原图（不重新压缩）；开发板会用冻结瞬间的关节读数把你给的像素换算成三维位置，所以**坐标必须是这张原图上的像素**。
- 你的服务**不能**触发运动，也没有任何“放行”“跳过检查”之类的选项；返回里出现协议之外的字段，Mac 端会整次拒绝，不提交。

---

## 2. 你要跑的服务

最省事：用仓库里的参考服务，把你的检测器类挂上去，不用自己写 HTTP。

```bat
REM 在仓库根目录，用你自己的模型环境（已装好 opencv、numpy 和你的模型依赖）
python pc\detect_server.py --detector block_vision.yolo_detector:YoloBlockDetector --host 0.0.0.0 --port 8100
```

- `--detector`：`模块:类名`，类需继承 `pc/block_vision/base.py` 的 `BlockDetector`，实现 `detect(image) -> List[BlockDetection]`（image 为 BGR numpy 原图）。你现有的检测器就是这个形状。
- 本地自检（不用开发板、不用 Mac）：`python pc\detect_server.py --detector ... --selftest 图片.jpg`，打印将要返回的 JSON。
- Windows 防火墙需允许该端口的入站连接（第一次运行时弹窗选“允许”，或在防火墙里放行 8100）。
- 把你电脑在局域网里的 IP（`ipconfig` 里 WLAN 的 IPv4）告诉控制同学。

如果你想自己实现服务（别的语言/框架），按下面第 3 节的协议即可。

---

## 3. 协议

### 3.1 `GET /health`

返回：

```json
{"protocol": "jjt-detect/1", "ready": true, "model": "yolo-top-face v3 (sha256 9A49…)"}
```

- `protocol` 必须是 `"jjt-detect/1"`，否则 Mac 端拒绝使用。
- `ready=false` 表示模型还在加载；`model` 是给人看的模型名/版本，会记进日志。

### 3.2 `POST /detect`

请求：

- Body：JPEG 原图字节（`Content-Type: image/jpeg`），当前 640×480。
- 请求头：`X-Frame-Id`（32 位十六进制，原样带回）、`X-Image-Width`、`X-Image-Height`。

成功返回（HTTP 200，`application/json`）：

```json
{
  "protocol": "jjt-detect/1",
  "frame_id": "与请求头相同",
  "model": "yolo-top-face v3",
  "ms": 85.2,
  "detections": [
    {"corners": [[412.0, 151.5], [298.0, 155.0], [301.5, 268.0], [418.0, 262.5]],
     "center": [357.4, 209.3],
     "score": 0.93,
     "label": "yellow"}
  ]
}
```

- 顶层只允许 `protocol`、`frame_id`、`model`、`ms`、`detections` 五个字段。
- `detections` 可以为空列表（没看到方块）；最多 20 个。Mac 端取 `score` 最高且不低于网页上设置的置信度下限的一个提交。
- 每个检测只允许这些字段：
  - `corners`：**方块顶面**四个角，沿轮廓顺序（顺/逆时针均可），第 1→2 角那条边决定夹爪方向。推荐用这个。
  - `bbox` + 可选 `angle_deg`：没有四角时的备选，`[left, top, right, bottom]`，角度为顶面一条边的方向（0°=水平，顺时针为正）。`corners` 与 `bbox` 二选一。
  - `center`（可选）：顶面中心；不给时由四角对角线交点或框中心得出。
  - `score`：0～1。
  - `label`（可选）：字符串，≤64 字，只用于日志。
- 坐标一律是原图像素，左上角为原点，u 向右、v 向下，必须落在图内（0 ≤ u < 宽，0 ≤ v < 高），必须是有限数值。
- **顶面**很重要：开发板按“30 mm 方块顶面四边投影长度”自校高度，如果你给的是整个方块轮廓（含侧面），位置会偏，四边长度不符时还会退回到误差更大的方式。

出错时返回 HTTP 4xx/5xx 和 `{"error": "原因"}`；Mac 端这次不提交任何东西，原因显示在 `/modes` 页面上，不会自动重试，控制同学再点一次按钮才会重新发图。

### 3.3 时间与网络

- Mac 端对 `/detect` 等待 10 秒，超时视为出错。冻结的帧在开发板上 2 分钟后过期，所以识别要在几秒内完成。
- 局域网直连，不经过代理；Mac 端已对该地址关闭代理。
- 暂不做鉴权：同一局域网内谁都能调用你的服务，但它只能返回像素结果，不能让机械臂动；结果还要经过 Mac 端校验、会话授权和开发板全部检查。

## 4. 联调步骤

1. 你：`--selftest` 用几张开发板拍的图确认四角画在方块**顶面**上。
2. 你：启动服务，在自己电脑浏览器打开 `http://127.0.0.1:8100/health` 能看到 `ready: true`。
3. 控制同学：在 Mac 上 `curl --noproxy '*' http://你的IP:8100/health` 能通。
4. 控制同学：先对本机模拟开发板联调（`board/simulate.py`），再上实机。Mac 上常驻运行
   `python pc/run_block_grasp.py --board http://192.168.137.100:8080 --detect-url http://你的IP:8100`，
   在开发板 `/modes` 页面开启“方块识别自动抓取”会话，每点一次“开始识别夹取”做一次完整识别夹取。

## 5. 不再需要的东西

- 你电脑上的 `pc/vision_service.py`（冻结 + 提交）、`pc/block_vision/grasp_once.py`、`capture_preview.py` 的冻结功能，以及你在开发板 `/modes` 页面加的“PC 识别抓取”面板，都由这套流程取代；它们不带按钮发出的一次性编号，开发板会拒绝。
- 你电脑不需要接开发板网线，也不需要装控制同学的规划环境。
