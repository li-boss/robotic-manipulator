## 1. 你要做的事（一句话）

写一个**方块检测器类**。它输入开发板摄像头的一张原图，输出图中方块**顶面四个角的像素坐标**。其余部分（冻结画面、坐标换算、逆解、路径碰撞检查、舵机控制）都已经做好，在开发板上运行。

最终效果：在网页上开启“方块识别自动抓取”模式后，电脑端程序会反复执行这几步，直到会话结束：
1. 让开发板冻结一帧画面。
2. 调用你的检测器。
3. 把得分最高的那块方块发给开发板。
4. 开发板规划路径并抓取，抓完再取下一帧。

## 5. 你要实现的接口

### 5.1 基类（`pc/block_vision/base.py`，已存在，不要改）

```python
class BlockDetector(ABC):
    @abstractmethod
    def detect(self, image) -> List[BlockDetection]:
        ...
```

- **输入** `image`：BGR 格式的 `numpy.uint8` 数组，形状 H×W×3，是开发板摄像头**原图**，当前为 **640×480**。来自 `Frame.image`，即 `cv2.imdecode` 解码后的 JPEG。
- **输出**：图中所有候选方块组成的列表，没找到就返回 `[]`。主循环会先过滤掉低于网页上“置信度下限”的结果，再取 `score` 最高的一个提交。
- 耗时的初始化（加载权重等）放在 `__init__` 里，`detect()` 会被反复调用。
- `__init__` 不能有必填参数：主循环用 `load_class("模块:类名")` 无参数实例化。需要配置时用默认参数或环境变量。

### 5.2 输出数据结构（`pc/armlink/types.py`）

```python
@dataclass
class BlockDetection:
    corners: Optional[Sequence[Point]] = None   # 推荐：顶面四个角 [(u,v)×4]，沿轮廓顺序（顺/逆时针都行）
    bbox: Optional[Sequence[float]] = None      # 备选：[left, top, right, bottom]
    angle_deg: Optional[float] = None           # 配合 bbox：顶面一条边在图中的角度，0°=水平，顺时针为正
    center: Optional[Point] = None              # 可选：顶面中心；不给时 corners 取对角线交点、bbox 取框中心
    score: float = 1.0                          # 置信度 0～1
    label: Optional[str] = None                 # 类别名，例如 'yellow'，只用于日志
```

坐标规则（非常重要）：
- 一律使用**原图像素**：原点在左上角，`u` 向右，`v` 向下。如果你缩放或裁剪了输入，必须换算回原图坐标。所有点都必须落在图内（0 ≤ u < 640，0 ≤ v < 480）。
- 要的是**顶面**：四个角是方块顶面那个正方形的角，中心是顶面中心，**不是**整块外轮廓（含侧面）的外接框或质心。摄像头常常斜着看，侧面也会入镜，侧面颜色和顶面一样。把侧面算进去，定位会偏几毫米到一厘米。
- 四个角必须构成凸四边形，不能交叉或共线，面积不能太小，否则开发板会拒绝。
- 方块边长 30 mm，是正方体，所以夹爪方向取任意一条顶面边都可以（开发板按 90° 对称处理）。
- 推荐用 `corners`。开发板会用顶面四条边投影到桌面的长度做单帧尺度自校；四个角越准，定位越准。只能给框时用 `bbox + angle_deg`，精度会差一些。

### 5.3 最小示例（新建 `pc/block_vision/my_detector.py`）

```python
from armlink import BlockDetection
from .base import BlockDetector


class MyDetector(BlockDetector):
    def __init__(self, weights='pc/block_vision/weights/best.pt', conf=0.5):
        # 在这里加载模型（只加载一次）
        self.model = load_model(weights)
        self.conf = conf

    def detect(self, image):
        results = []
        for obj in self.model(image):            # 你的推理
            if obj.score < self.conf:
                continue
            results.append(BlockDetection(
                corners=obj.top_face_corners,      # [(u,v),(u,v),(u,v),(u,v)]，原图像素
                score=float(obj.score),
                label=obj.cls_name))
        return sorted(results, key=lambda d: d.score, reverse=True)
```

参考实现：[pc/block_vision/color_detector.py](../pc/block_vision/color_detector.py)。它用 HSV 阈值加最小外接矩形，只够跑通流程。斜视时它会把侧面也框进去，这正是你的模型要解决的问题。

### 5.4 主循环做了什么（`pc/run_block_grasp.py`，已写好）

1. `client.wait_for_mode('block_grasp')`：等待网页开启模式，拿到 `session_id`、`min_score`、`max_actions`。
2. 每一轮：
   1. `client.freeze_frame(session)` 冻结一帧，得到 `Frame`（`frame_id`、`jpeg`、`image_size`、`joints`）。
   2. 调用 `detector.detect(frame.image)`，过滤掉 `score < min_score` 的结果，取得分最高的一个。
   3. `client.submit_block(session, frame_id, best)` 提交。开发板会依次：定位 → 规划（一般约 4 秒，电脑端规划服务没开时约 15 秒）→ 碰撞检查 → **自动执行**。
   4. `client.wait_job(job_id)` 等待抓取结束，再进入下一轮。
3. 以下情况会结束本次会话，程序随之退出：次数用完、超时、任一步失败、网页点“关闭模式”，或在电脑端按 Ctrl+C（会请求结束会话；已发出的动作无法撤回，不是急停）。

### 5.5 底层 HTTP 接口（主循环已封装，一般不用手写）

基地址 `http://192.168.137.100:8080`，模拟时为 `http://127.0.0.1:8092`。

| 方法 路径 | 请求 | 响应 | 会不会动 |
|---|---|---|---|
| `GET /api/v1/health` | — | `{service, api_version:1, mode:"real"/"simulation", camera, busy}` | 不动 |
| `GET /api/v1/mode` | — | `{armed, kind, session_id, used, max_actions, expires_in, busy, task_mode, min_score, message}` | 不动 |
| `GET /api/v1/job` | — | `{busy, job:{id, status, sent, total, message, error}}` | 不动 |
| `GET /api/v1/frame.jpg` | — | 最新一帧 JPEG（不冻结） | 不动 |
| `POST /api/v1/block/frame` | `{session_id}` | `{frame_id, image_size, captured_at, joints, jpeg_base64}` | 不动 |
| `POST /api/v1/block/target` | `{session_id, frame_id, detection:{corners | bbox+angle_deg, center?, score, label?}}` | `{job:{id,status}, target:{xyz_mm, edge_yaw_deg, destination_xy_mm,…}, steps, warnings, used}` | **会动**（会话已授权） |
| `POST /api/v1/stop` | `{session_id?}` | 结束会话 | 停止后续动作 |

失败时返回 HTTP 400/503 和 `{"error": "中文原因"}`，`BoardClient` 会把它抛成 `BoardError(message, status)`。

## 8. 收集真实训练 / 测试数据

- 训练数据必须来自**开发板摄像头**：它装在机械臂末端，640×480，带畸变，斜视桌面。
- 方法 1（推荐）：实机上开启模式后，加 `--save-frames DIR` 运行，每次冻结的原图会存到 `DIR`。这一步需要在场的人在网页上开启模式，并且会真的抓取。
- 方法 2：浏览器打开 <http://192.168.137.100:8080/api/v1/frame.jpg> 反复保存，或写个小脚本循环 `GET /api/v1/frame.jpg`。这只读取画面，**机械臂不动**。可以先由在场的人用首页姿态按钮把机械臂摆到不同的观察姿态，再采集。
- 方法 3：请机械臂控制同学从开发板导出 `board/data/logs/manipulation/frames/*.jpg`，这些是历史冻结图。
- 标注建议：每块方块标**顶面四个角**（关键点或多边形），而不只是外接框。不同颜色、距离、光照、倾斜角度和遮挡都要覆盖。

## 10. 常见拒绝原因（开发板返回的中文提示）

| 提示里包含 | 含义 / 怎么办 |
|---|---|
| `模式未开启` / `会话编号不符` | 网页上还没开启，或者已经重开；重新运行主循环即可 |
| `置信度` / `min_score` | score 低于网页上设置的下限 |
| `角点` / `凸` / `交叉` / `共线` / `超出原图` | corners 不合法：顺序错乱、点在图外、面积太小 |
| `方块边缘超出已核对桌面区域` | 方块不在可抓取的桌面范围内 |
| `本帧方块尺寸自校未采用` | 只是警告：四个角和 30 mm 边长对不上，多半是框进了侧面，或角点不准 |
| `取物点距底座约…毫米…（快速预检）` | 方块离底座太远或太近，机械臂够不到，请移动方块 |
| `取放区域重叠` | 方块就在放置点附近，先把放置点清空 |
| `电脑端规划未通过` / `九点引导…未通过` | 该位置或方向没有安全路径，换个位置 |

## 11. 测试与交付

- 本地测试（不连硬件）。Mac/Linux：

```bash
zsh tools/run_tests.sh
```

  Windows 只跑电脑端测试：

```powershell
python -m unittest discover -s pc\tests -p "test_*.py"
```

- 给你的检测器写一个小测试，放在 `pc/tests/test_block_<名字>.py`：喂一张已知图片，检查返回值是 `BlockDetection` 列表、四个角都在图内、`score` 在 0～1 之间、`to_dict()` 不报错。没有权重时用 `unittest.skipUnless` 跳过，不要让别人的测试因为缺少权重而失败。
- git：在分支 `feat/block-vision` 上开发，只提交 `pc/block_vision/`、`pc/tests/` 和你的依赖文件，然后提合并请求，由机械臂控制同学 review。**不要直接推 main**，不要提交权重或训练数据。
- 交付前检查清单：
  - [ ] 在 `board/simulate.py` 上完整跑通（`--once`，结果为 completed）
  - [ ] 坐标是原图像素、顶面四角、点都在图内
  - [ ] `__init__` 无必填参数，`--detector 模块:类名` 能加载
  - [ ] 依赖已写进 `pc/block_vision/requirements.txt`，权重下载方式写清楚
  - [ ] 测试通过，且没有连接真实机械臂

## 12. 迁移你已有的代码（旧结构 → 新结构）

2026-11-06 起，main 换成了本结构，旧的 `mechanical_arm/` 等目录已不在 main 的最新版本里。旧版本没有丢失：
- 在提交 `fd90b0f` 里；
- 你自己的分支（例如 `codex/a-vision-top-face-20261031`）也原样保留。

以新的 main 为基础开分支，再把旧分支里**你自己写的识别代码**挪到 `pc/block_vision/`：

```bash
git fetch origin && git checkout -b feat/block-vision origin/main
```

查看旧分支里有哪些文件：

```bash
git diff --stat fd90b0f origin/codex/a-vision-top-face-20261031
```

取回某个文件作参考：

```bash
git show origin/codex/a-vision-top-face-20261031:<路径> > /tmp/参考.py
```

迁移要点：
- 把识别逻辑包装成 `BlockDetector` 子类：`detect(image)` 返回 `BlockDetection(corners=顶面四角, score, label)`，坐标用原图像素。
- 旧结构里直接调用开发板抓放接口、或者提交关节角度的代码**不要再用**：只通过 `run_block_grasp.py` 和 `BoardClient`，在网页开启的模式会话里提交像素位置。
- 不要直接合并旧分支：旧分支基于旧结构，会把 `mechanical_arm/` 等旧目录带回来。
