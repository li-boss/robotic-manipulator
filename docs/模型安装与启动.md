# 模型安装与启动（方块识别 A / 手势表情 D）

本文把两套模型的**安装、权重获取、启动命令、自检方式和常见故障**写在一起。所有命令都在本机实测过（2026-11-09 ~ 11-10，Windows 10/11 + 有线网卡 `192.168.137.102`，开发板 `192.168.137.100`）。

> 一句话结论：**两个模块在同一台电脑上、用两个互不影响的 Python 环境**。方块识别用现成的 `.venv-train`（Python 3.10），手势表情用新建的 `G:\venv-d313`（Python 3.13）。不要装进同一个环境。
>
> 各权重的文件名、大小、SHA-256 与获取方式见 [训练权重清单.md](训练权重清单.md)（语音模块的 WeNet 模型也在那份文档里）。

## 0. 版本对照（以实测为准）

| 项目 | A：方块识别 | D：手势 / 表情 |
|---|---|---|
| Python | 3.10.11 | **3.13.5** |
| 解释器 | `G:\robotic-manipulator\data\a_blocks\.venv-train\Scripts\python.exe` | `G:\venv-d313\Scripts\python.exe` |
| torch | 2.7.1+cpu | **2.13.0+cpu** |
| numpy | 2.2.6 | **2.4.3** |
| 视觉库 | opencv-python 5.0.0.93 | opencv-contrib-python 5.0.0.93 |

| 依赖清单 | `pc/block_vision/requirements.txt` | `pc/gesture/requirements.txt` |

## 2. A：方块识别

### 2.1 环境（已装好就直接用）

复用现有环境，不要重建：

```powershell
$pyA = 'G:\robotic-manipulator\data\a_blocks\.venv-train\Scripts\python.exe'
& $pyA -c "import sys,torch,numpy,cv2,ultralytics;print(sys.version.split()[0],torch.__version__,numpy.__version__,cv2.__version__,ultralytics.__version__)"
# 期望：3.10.11 2.7.1+cpu 2.2.6 5.0.0 8.4.183
```

换电脑时从零安装：

```powershell
& 'C:\...\python.exe' -m venv .venv-block            # 需 Python 3.10
.\.venv-block\Scripts\python.exe -m pip install -r pc\block_vision\requirements.txt
```

### 2.2 权重（不入库，必须单独拿到）

`pc/block_vision/weights/` 已被 `.gitignore` 忽略。把 `best.pt` 从 A 的机器上复制过来后**先校验哈希**：

```powershell
Get-FileHash pc\block_vision\weights\best.pt -Algorithm SHA256
# 期望：9A493D49070ADAE232CFC00F6B2E30965726F761B12367EDE119D716C38D975A
```

也可用环境变量指向别处的权重与阈值文件：

```powershell
$env:BLOCK_VISION_WEIGHTS     = 'D:\models\best.pt'
$env:BLOCK_VISION_HSV_CONFIG  = 'D:\models\a_top_face_hsv.json'
```

缺文件、类别顺序不对、推理失败都会**明确报错**，不会静默降级。

### 2.3 自检（不连板端）

```powershell
# 1) 用一张本地图跑完整插件并出叠加图
& $pyA pc\block_vision\grasp_once.py --image <某张现场图>.jpg --label block_yellow
# 期望：打印 YOLO 框数、插件候选数、所选黄块的 score/中心/四角

# 2) 取一帧板端快照（需要板端服务在跑）
& $pyA pc\block_vision\capture_preview.py --out pc\block_vision\weights\snap_$(Get-Date -Format HHmmss) --scene check
# 期望 capture.json 里 "source_type": "new_board_snapshot_without_freeze"

# 3) 画可达范围环（判断方块放得够不够近）
& $pyA pc\block_vision\reach_help.py --label block_yellow
# 期望：radii_mm = [132.8, 319.0]，analysis_lab\reach_*.png
```

### 2.4 启动：三种用法

**① 只看一帧（不运动）**

```powershell
& $pyA pc\block_vision\capture_preview.py --out <新目录> --scene current
```

**② 单次抓取（需要先在网页 `/modes` 开启会话）**

```powershell
# 冻结 + 识别 + 打印，不提交
& $pyA pc\block_vision\grasp_once.py --stage --label block_yellow --out <新目录>
# 核对后提交同一帧（同一 session_id / frame_id / detection）
& $pyA pc\block_vision\grasp_once.py --submit "<上一步的目录>"
```

**③ PC 控制台（页面按钮，推荐日常用）**

```powershell
& $pyA pc\vision_service.py --host 0.0.0.0 --port 8099 --board http://192.168.137.100:8080
# 浏览器打开 http://192.168.137.102:8099/
```

页面两个按钮：`① 冻结并识别（不运动）` → `② 开始抓取（会运动，弹确认框）`。冻结结果 90 秒内有效（`--max-age` 可调），过期必须重冻；服务只接受来源在白名单里的页面调用。

## 3. D：手势与表情

### 3.1 环境（Python 3.13.5）

板端与 A 侧都不提供 3.13，需要单独装一份**当前用户级**解释器（不要管理员权限、不改系统 PATH）：

```powershell
Invoke-WebRequest 'https://www.python.org/ftp/python/3.13.5/python-3.13.5-amd64.exe' -OutFile .\py313.exe
Start-Process .\py313.exe -Wait -ArgumentList '/quiet','InstallAllUsers=0','TargetDir=G:\Python313',
  'Include_launcher=0','Include_test=0','Include_pip=1','PrependPath=0','AssociateFiles=0','Shortcuts=0'

G:\Python313\python.exe -V                     # 期望 Python 3.13.5
G:\Python313\python.exe -m venv G:\venv-d313
G:\venv-d313\Scripts\python.exe -m pip install -r pc\gesture\requirements.txt
```

装完自检：

```powershell
$pyD = 'G:\venv-d313\Scripts\python.exe'
& $pyD -c "import sys,torch,numpy,cv2,mediapipe;print(sys.version.split()[0],torch.__version__,numpy.__version__,cv2.__version__,mediapipe.__version__)"
# 期望：3.13.5 2.13.0+cpu 2.4.3 5.0.0 0.10.35
```

> 该 `mediapipe 0.10.35` 只提供 `tasks` API，没有旧版 `mp.solutions`。D 的代码用的是 `mp.tasks.vision.HandLandmarker / FaceLandmarker` + `mp.Image`，与之匹配，不需要改代码。

### 3.2 模型资产（不入库，脚本下载并校验）

```powershell
& $pyD pc\gesture\download_assets.py
# 期望三行 "Installed and verified"：
#   best_hand_gesture_classifier.pt   42 MB
#   hand_landmarker.task             7.8 MB
#   face_landmarker.task             3.8 MB
```

脚本对每个文件做 SHA-256 校验，**哈希不符直接拒写**（定义在 `pc/gesture/assets.py`）。已有文件只会校验，不会覆盖。离线环境可用 `--from-local <旧 emotion_interaction/models 目录>`。

### 3.3 自检（不连板端）

```powershell
& $pyD -c "import sys,numpy as np;sys.path.insert(0,'pc');from gesture.recognizer import CombinedRecognizer;r=CombinedRecognizer();print(r.recognize(np.zeros((480,640,3),np.uint8)));r.close()"
# 期望：打印 None（空白帧没有手势），说明模型加载、推理、释放都通
```

日志里的 `XNNPACK delegate` / `Feedback manager` 是 mediapipe 的正常信息输出，不是错误。

### 3.4 启动

```powershell
# 先在网页 /modes 开启「表情手势跳舞」并确认，再运行：
& $pyD pc\run_gesture_dance.py --board http://192.168.137.100:8080
```

常用参数：`--recognizer`（默认 `gesture.recognizer:CombinedRecognizer`）、`--source`（默认读板端快照）、`--map`（label→舞蹈动作）、`--stable`（连续确认帧数）、`--threshold`。

## 4. 板端服务（两套模型都依赖它）

### 4.1 启动

在**板端 SSH 窗口**（不是电脑 PowerShell）：

```bash
cd /root/jjt/board
/root/miniconda3/envs/ros-arm-env/bin/python -u -B start_service.py \
    --enable-real-control --enable-ros-planner --no-pc-planner
```

- `--enable-real-control`：实机控制。**不加则为模拟模式**，此时冻结帧里的六关节是假值（固定 90），不能用于真实抓取。
- `--enable-ros-planner`：启动 ROS2 纯计算节点做独立比对；计划参数不一致会整体拒绝。
- `--no-pc-planner`：不用电脑端规划（默认地址是 `192.168.137.101:8095`，与现在电脑 `192.168.137.102` 不一致，建议显式关闭，省一次 1.5 s 超时）。

成功标志：最后一行 `网页服务PID=…；启动不运动，实机启用=True`。

### 4.2 四项只读验证

```bash
curl -s http://192.168.137.100:8080/api/v1/health      # mode=real、camera.connected=true、640x480
curl -s http://192.168.137.100:8080/api/v1/mode        # armed=false（还没开会话）
curl -s -o /tmp/f.jpg -w 'frame=%{http_code}\n' http://192.168.137.100:8080/api/v1/frame.jpg   # 期望 200
curl -s http://192.168.137.100:8080/manipulation/status | head -c 400   # execution_readiness.ready=true、issues=[]
```

在电脑侧同样可以验：`Invoke-WebRequest http://192.168.137.100:8080/api/v1/health`。

### 4.3 授权与提交（顺序不能乱）

1. 浏览器打开 `http://192.168.137.100:8080/modes`，任务类型选「只夹取并抬升」、次数 1、置信度下限 0.5、有效期 10 分钟 → 勾选确认 → **开启模式**。
2. 电脑端冻结一帧（`grasp_once.py --stage` 或页面 `① 冻结并识别`）。
3. 由人核对叠加图与关节读数后触发提交（`--submit` 或页面 `② 开始抓取`）。
4. 板端自行定位 → 全路径碰撞/扫掠检查 → ROS2 比对 → 执行前再读一次关节（与冻结读数差 >1° 就拒绝）。

> 冻结到提交之间**不要碰机械臂、不要移动方块**。`pickup`（只夹取）结束时保持夹持、不自动松爪。

## 6. 常见故障与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: ultralytics` | 用 3.13 环境跑了 A 侧脚本 | 换 `$pyA`（`.venv-train`） |
| `No module named 'mediapipe'` | 用 3.10 环境跑了 D 侧脚本 | 换 `$pyD`（`G:\venv-d313`） |
| `六关节读取不完整，禁止执行或保存` / `无效读数：None` | 某个关节停在库的读数窗口（脉宽 900–3100）之外，常见于顶到限位 | 断电，把那个关节往中位挪 10–20° 后上电复测：`d.Arm_serial_servo_read(i)` 六个都要是整数 |
| `取物点距底座 340 毫米，超出…133～319 毫米` | 方块太远 | 把方块往底座方向挪，或用 `reach_help.py` 看 319 mm 环；中心要落在环的**近端** |
| `review frame_boundary` / 候选 0 个 | 方块被画面边缘裁掉 | 让整块都在画面内（下缘留 ≥30 px） |
| `板端拒绝（400）：检测置信度低于本会话下限` | 网页会话的 `min_score` 高于模型分数 | 重开会话把下限调低，或换更清晰的摆位 |
| `会话已变` / `没有已开启的 block_grasp 会话` | 会话过期（默认 10 分钟）、次数用完或服务重启 | 重新在 `/modes` 开启模式 |
| `冻结已过期（>90s）` | 冻结后停留太久 | 重新冻结 |
| `连不上 PC 服务（8099）` | `vision_service.py` 没跑 / 电脑休眠 / 防火墙 | 重启服务；防火墙放行 8099 入站 |
| `cv2.calibrateHandEye` 不存在 | OpenCV 5.0.0 没有该函数（板端 4.6 有） | 板端标定测试在板端跑；PC 上不复现该测试 |

## 7. 已知限制

1. **两套环境不能合并**：torch 2.7.1 / numpy 2.2.6（A）与 torch 2.13.0 / numpy 2.4.3（D）冲突，`ultralytics` 与 `mediapipe` 同时装会互相拉扯。
2. **权重不入库**：A 的 `best.pt`、D 的三个模型文件都要按第 2.2、3.2 节单独获取并校验哈希；换电脑必做。
3. **PC 端规划器未启用**：默认地址仍是 `192.168.137.101:8095`，与现在的 `192.168.137.102` 不一致；要用需改 `--pc-planner` 或启动 `plan_server.py`。
4. **手势只做了空白帧冒烟**：识别率需要在真实摄像头与光照下另做验收，文档不代替现场测试。
5. **`pickup` 不自动松爪**：抓完要保持夹持，放开需要另一次运动授权（网页首页单关节 6 号 → 90）。
