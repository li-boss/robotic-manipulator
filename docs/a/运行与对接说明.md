## 在 Windows PowerShell 启动真实图片检测

在 **G 盘项目目录**打开 PowerShell：

```powershell
Set-Location -LiteralPath 'G:\robotic-manipulator'
& 'data\a_blocks\.venv-train\Scripts\python.exe' -m camera_service.service --mode image --source 'data\a_blocks\formal_v1_20261022\images\val\414.jpg' --backend yolov8n --weights 'data\a_blocks\runs\yolov8n_formal_v1_cpu_20261022_01\weights\best.pt' --model-conf 0.25 --nms-iou 0.5 --imgsz 640
```

启动先显示 `YOLO startup warmup: ... ms`，之后显示 `A service at http://127.0.0.1:8765; mode=image; backend=yolov8n`。预热只初始化预测器，不生成用户帧或请求缓存；预热失败服务直接停止并报 `MODEL_WARMUP_FAILED`，不回退 mock。权重只在服务启动时加载一次。按 Ctrl+C 停止。当前已实测环境为 Python 3.10.11、torch 2.7.1+cpu、Ultralytics 8.4.183；GPU/Atlas 未验证。缺权重或权重损坏时启动直接报错，不会改用 mock。

另开 PowerShell，先查询 `Invoke-RestMethod http://127.0.0.1:8765/api/v1/ready`；只有 `status=ready` 且 `model_ready=true,camera_ready=true,simulated=false` 时再由 C 调用（每次新检测使用新的 `request_id`）：

```powershell
$meta = Invoke-RestMethod 'http://127.0.0.1:8765/api/v1/frames/latest/meta'
$body = @{request_id='c-real-001'; frame_id=$meta.frame_id} | ConvertTo-Json
$result = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8765/api/v1/detect' -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$result | ConvertTo-Json -Depth 8
```

也可传 `frame_id='latest'`；服务在首次处理时把它解析为实际帧 ID。同一 `request_id` 加同一请求返回缓存的完全相同响应；同一 ID 改传另一帧会返回 `BAD_REQUEST`。服务重启后缓存清空。成功响应保留 `request_id, frame_id, camera_id, captured_at, image_width, image_height, coordinate_space, transform_version, outcome, targets, inference_ms, processing_ms, simulated`；本轮追加 `inference_started_at, inference_finished_at, frame_age_at_finish_ms, frame_valid_until`。`inference_started_at`、`inference_finished_at`、`frame_valid_until` 均为 Unix 毫秒，`frame_age_at_finish_ms` 是推理结束时的帧龄毫秒数；有效截止时间为采集时间加最大有效期；静态图片模式无期限，返回 null。检测结束时断流返回 `CAMERA_UNAVAILABLE`，帧龄超限返回 410 `FRAME_EXPIRED`，错误体含上述三个时点和有效期诊断，不会给旧坐标。目标含 `target_id, raw_label, category, confidence, bbox, center_x, center_y, target_status`。真实样例见 [HTTP 请求响应记录](../../data/a_blocks/evaluations/yolov8n_formal_v1_cpu_http_20261023_01/http_samples.json)。

D 获取**同一帧完整原 JPEG**：

```powershell
Invoke-WebRequest -Uri ("http://127.0.0.1:8765/api/v1/frames/" + $result.frame_id) -OutFile 'G:\robotic-manipulator\data\a_blocks\d_frame_check.jpg'
```

此处 `$result` 必须是上一条**成功检测响应**；使用其中实际 `frame_id` 才能保证 D 取的是该次检测对应原图。原帧过期或已从缓存移除时，按错误处理，不能重新查询 `latest` 并冒充同帧。元数据含帧 ID、电脑发布时间、分辨率、编码和坐标空间。实时帧默认 500 ms 后过期。实际摄像头视角能否同时看到工作区和人脸仍需设备实测。

## 后端、异常与线程边界

`none`、`mock` 启动行为不变；例如协议测试可显式运行 `--backend mock --fixture configs\mock_blocks.json`。真实模型正常无目标返回 `outcome:no_target, targets:[], simulated:false`；模型失败返回 `INFERENCE_FAILED`，不生成目标。缺模型、坏权重、无效帧、过期帧分别保留明确错误。低于 Detector 的 0.5 状态阈值时标记 `low_confidence`；业务类别未映射时为 `unmapped`。固定图上的高阈值 `no_target` 与低置信度路径已测试，**高阈值空结果不是空场景识别验证**。

服务采用 `ThreadingHTTPServer`；`VisionService` 的锁把检测及 `request_id` 缓存操作串行化，YOLO 后端另用锁保护 Ultralytics 预测器。相同 `request_id` 的重放保留原结果，属于历史响应；C 在动作调度前还须核对 `frame_valid_until` 与当前时间，过期响应不能被当作新目标。`FrameStore` 单独加锁；D 的帧读取不需要再次打开摄像头，也不等模型推理锁。模型后端先从帧 JPEG 解码，核对 640×480；Ultralytics `boxes.xyxy` 已对应 `result.orig_shape` 原图，不做第二次 letterbox 坐标还原。超出原图的真实框会报错，避免靠强制裁剪掩盖错误；mock 原有变换行为保留。B 应使用同一 `raw_camera` 坐标空间的标定，不由 A 发送动作指令。

## C/D 联调网络与计时约定

同机使用 `http://127.0.0.1:8765`；其他电脑的 `127.0.0.1` 指向其自身，不能访问 A 的服务。局域网联调时先确认 A 电脑的私有 IPv4，例如 `192.168.1.23`，由 A 在启动命令末尾追加 `--host 192.168.1.23 --port 8765`，C/D 使用 `http://192.168.1.23:8765` 的相同路径；只在受信任的专用/私有网络允许 Windows 防火墙入站 TCP 8765，并用另一台电脑试 `/api/v1/ready`。服务拒绝 `0.0.0.0` 和公网地址绑定；当前未做跨电脑联调，服务也没有鉴权，不要做公网端口映射。

`captured_at` 为 **A 电脑发布帧**的 Unix 毫秒；图片模式是文件读入时间，MJPEG 模式是电脑解码后发布时间，均不是板端曝光时间。`inference_started_at`/`inference_finished_at` 是 A 服务开始/结束一次检测的时刻。原 `inference_ms` 为整个后端 `infer()` 耗时，**包括 JPEG 解码、Ultralytics 预处理、模型执行、后处理及输出解析**，不是纯神经网络推理时间；`processing_ms` 为服务内帧查找、后端检测和封装耗时，不含 HTTP 传输及客户端时间。新增就绪响应提供权重／配置摘要、算法版本、运行参数及时间含义；旧字段不变。板端纯推理性能仍未测试。

B 须确认相机安装、标定使用的 `raw_camera` 空间和机械臂对应关系；A 提供图像、旧框中心和可选的顶面像素候选点，不发送动作。D 如需同时看人脸和工作区，须在实机确认相机视角是否覆盖。新拍的独立测试**照片**仍放入上面的独立目录，人工标注后按原评估入口操作，现场采样不会自动加入训练集。
