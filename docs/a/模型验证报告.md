## 模型效果与数据限制

正式 CPU 基线 62 轮，第 42 轮最佳；原 206 张均有人工作业标签，`321.jpg/399.jpg/439.jpg` 的 3 处极小误框待人工修正，正式版本排除这三图。训练 143 图、验证 60 图。旧集合验证集 mAP@0.5=0.995，四类 AP@0.5 均 0.995，60 图预测在 conf=0.25/NMS IoU=0.5 下无程序诊断的漏检、错类或重复框。414.jpg 在本轮 val，由三轮试训的 10 个混乱候选改善为 4 个对应的候选。[人工真值与正式预测对照](../../data/a_blocks/evaluations/yolov8n_formal_v1_cpu_val_20261022_01/gt_vs_prediction/414.png)。旧图存在相似背景、物体和姿态；没有新拍摄独立测试或人工确认空场景，**识别效果是否达到项目要求仍证据不足**。四个标签只是积木顶面颜色，不代表业务四类垃圾。

新照片入口和准备/封存脚本已写并通过命令解析检查，但因为尚无新照片，标注、封存和独立评估**未运行**。GPU 环境、Atlas 导出转换与板端运行均未验证。此前训练过程和较长历史记录已[归档](archive/2026-10-23_真实API接入前_模型验证报告.md)。


## 本轮启动预热与摄像头入口检查（2026-10-23）

证据保存在 [camera_prep_20261023_01/verification.json](../../data/a_blocks/evaluations/camera_prep_20261023_01/verification.json) 及同目录的 `image_server.log`、`camera_server.log`。正式 CPU 权重和旧训练数据/产物均未改变。

| 实测项目 | 结果与边界 |
|---|---|
| 图片服务启动预热 | 真实 YOLOv8n 启动预热 2648.619 ms；预热用内部黑图初始化预测器，未发布帧、目标或 `request_id`。启动后就绪端点为 200。预热失败路径通过自动测试验证，返回 `MODEL_WARMUP_FAILED` 并使服务无法启动。 |
| 预热后首次请求 | 固定旧图 414.jpg：后端 `inference_ms=64.307` ms，HTTP 客户端 66.671 ms。与修改前首请求 2619.389 ms 的口径不同，后者含预测器初始化；一次样本不能代表稳定速度分布。 |
| 检测与 D 取图并发 | 图片模式并发时，D 用同一 `frame_id` 取图耗时 16.563 ms，字节与先前获取的原图一致；相同 `request_id` 重复请求结果完全相同。这只证明本机静态图服务读取不等检测锁，未证明真实摄像头持续工作时的延迟。 |
| 摄像头可用性 | OpenCV 的 DirectShow、MSMF、默认入口均无法打开索引 0–2；Windows PnP 查询被拒绝访问。真实后端以 `--mode camera --source 0` 启动后 `/api/v1/ready` 返回 503：`model_ready=true,camera_ready=false,camera_error=CAMERA_UNAVAILABLE`；检测返回 503。不能据此判定物理设备一定不存在，需现场检查接线、权限和索引。 |
| 帧过期与断流 | 自动测试令检测跨过有效期或在推理中将采集源标为不可用，分别得到 `FRAME_EXPIRED`、`CAMERA_UNAVAILABLE`，不返回目标。真实摄像头断流与恢复仍未实测。 |

实际摄像头的连续帧、四类实物、空场景、光照变化、跨电脑 C/D 联调均待现场；已备 [现场采样脚本](../../tools/camera_field_test.py) 保存原图、预测叠加图、HTTP 响应、D 同帧取图耗时与断流/恢复记录。业务 `category` 继续为 null，四种颜色与垃圾类别的对应关系仍待团队确认。A 的原图坐标需 B 基于真实安装做标定；这轮没有发送机械臂动作。
