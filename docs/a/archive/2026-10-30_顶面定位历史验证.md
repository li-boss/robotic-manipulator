# 彩色顶面中心定位：开发验证（2026-10-30）

## 范围与接口边界

正式 YOLOv8n 权重和基线参数保持不变：`imgsz=640`、`conf=0.25`、NMS IoU `0.5`。电脑 CPU 推理，板端摄像头仍由原有服务采集。新增功能由 `--top-face` 显式启用；默认检测 API 及 mock 行为不变。`bbox`、`center_x`、`center_y` 始终是 **YOLO 检测框及框中心**。顶面定位只增加每个目标的可选 `top_face` 对象和响应级 `top_face_ms`，没有改写旧字段。公共 contracts 由 C 维护，A 未覆盖。

`top_face.candidate_point` 为 `raw_camera` 原图像素坐标；`top_face.visible_centroid` 是分割得到的可见颜色区域质心，两者含义不同。`status=candidate` 只表示本次分割轮廓通过几何检查，**不表示已标定或可执行夹取**。`status=review` 时 `candidate_point=null`，原因写在 `reason`。业务 `category` 和 `target_status` 仍按原映射处理；目前四类垃圾映射未确认，真实目标仍为 `category:null`、`target_status:unmapped`。

## 实现方法

1. 仅用本次检测的**同一张原图 JPEG** 和 YOLO 框，在适度扩展的局部 ROI 中做对应 `block_blue/green/red/yellow` 的 HSV 分割。阈值配置在 `configs/a_top_face_hsv.json`，当前版本 `experimental-hsv-20261030-v3-roi`，由已保存的 Atlas 640×480 画面调试得到。课程资料只提及标定板轮廓，没有可直接复用的积木彩色顶面定位源码。
2. ROI 按框宽高各向外扩展 8%，且限制在原图内。3×3 开运算与 5×5 闭运算去掉小噪声；筛掉过小区域。局部坐标加回 ROI 原点。诊断分别记录图像边界、原框边界、扩展 ROI 边界；碰到原框边界不再自动拒绝，碰到 ROI 边界仍要求复核。所选连通域至少 65% 位于原 YOLO 框内，多个相近候选区域、图像越界及过细长的连通区域要求复核；同类目标若认领高度重叠的彩色四边形也要求复核。
3. 对候选轮廓检查位置、凸性、实心度、四边形边界吻合度、面积比和长宽比。只有可靠拟合为四边形时，才求其**两条对角线交点**作为 `candidate_point`。不能拟合时可保留 `visible_centroid` 作参考，不把它冒充完整顶面中心。没有成功轮廓时两种点均可为空。
4. 可视化保留黄色 YOLO 框、橙色可见颜色区域、绿色四边形轮廓。紫色十字只画在有效顶面候选点；调试模式可另画青色叉表示旧框中心。定位不可靠时显示“顶面中心待确认”，不画紫色十字。图下方的文字栏显示类别、置信度、原图像素坐标与方法，不挡顶面。

这些检查降低了明显误用风险，无法证明在所有光照、遮挡或相似颜色背景下都能正确区分顶面与侧面。普通 2D 框和颜色分割也不能推断夹爪角度。

## 接口例子与 C/B 对接

显式启用后，一个目标仍保留原有 `bbox`、`center_x`、`center_y`，新增：

```json
{
  "center_x": 222.995,
  "center_y": 233.985,
  "top_face": {
    "status": "candidate",
    "reason": null,
    "coordinate_space": "raw_camera",
    "method": "quadrilateral_diagonal_intersection",
    "candidate_point": {"x": 222.25, "y": 199.499},
    "visible_centroid": {"x": 221.939, "y": 201.698},
    "quad": [[228,119],[127,200],[216,287],[317,199]],
    "quality": {"threshold_version": "experimental-hsv-20261030-v3-roi", "region_area_px": 17055}
  }
}
```

`visible_contour`、其他质量数值和 `top_face_ms` 也在实际 JSON 中。待复核或失败时 `candidate_point` 为 JSON `null`，无 `(0,0)` 默认点。旧消费者可忽略两个新增字段。C 若采用新点，应在其 contracts 中增加可选结构，并同时检查 `top_face.status`、`target_status`、`category`、帧有效期及 B 的标定结果；不能只凭 `simulated=false` 或 YOLO 置信度发动作。

B 需要确认该相机是固定安装，并提供顶面所在高度对应的标定或几何模型、原图尺寸及变换版本、像素到机械臂基坐标系的实测对应点与检查点、实际夹爪容差和安全位姿。桌面平面标定不能无条件用于积木顶面。A 本轮没有真实机械臂坐标、抓取高度、夹爪角度或试抓结果。D 的原图和帧元数据路径未变。

## 仍需场景

- 实时流再验证：本轮检查时 `192.168.137.100:8080` 连接超时，电脑原“以太网 3”未出现；用户确认本轮暂不连接。
- 真实顶面被遮挡、同色积木相邻且接触、相似颜色背景、明显反光/阴影与不同实际光照；需保存原图和人工复核。实验版会对已知几何异常给 `review`，不能保证识别所有复杂场景。
- 用户用 `tools.top_face_reference_labeler` 在**原图**上逐点复核四角，重新生成误差报告。未复核之前不设抓取允许误差。
- 实机标定、停在目标上方核对偏差和试抓由 B/C 在安全流程中进行。顶面像素点必须继续沿用同一 `frame_id` 和 `raw_camera` 空间。

## 2026-10-30 ROI 与复核口径更新

**已修复：**原实现把颜色区域碰到检测框边缘直接当作顶面被截断；现用可配置的 8% ROI 扩展，并区分原框、ROI 和图像边界。配置新增 `roi_expand_fraction`、`min_original_box_overlap`，启动时检查 HSV、图像尺寸和几何阈值范围；红色仍采用 HSV 两段色相范围，不自动放宽低饱和反光或阴影。轮廓凸性、实心度、四边形拟合面积比与 IoU 仍是互补的几何诊断；它们**不能证明选中的是顶面**。同色侧面和相似颜色背景仍可能形成规整四边形，需要真实反例和人工复核。

**正式参考与评价：**旧 12 个四角点为助手粗标，仍保留作历史开发记录，绝不自动标为用户确认。新版 `tools.top_face_reference_labeler` 默认只显示原图及 YOLO 框，隐藏算法点/轮廓；可返回上一目标、清空重画、跳过、标“顶面不完整”或“无法判断”。新记录包含原图 SHA-256、`frame_id`、尺寸、四角、复核状态及 `manual-raw-corners-v2` 版本。`tools.top_face_validate` 仅以 `review_status=confirmed` 的四角计算像素误差，并检查原图哈希及四角凸性；报告候选比例、复核比例、已确认不完整顶面上的错误接受数、有效候选误差中位数/P95/最大值和样本数。**本轮尚无用户确认四角记录，所以这些正式误差和错误接受率暂无结论**；旧 2.265 px 对 37.663 px 仍只是助手粗标初步证据。新批次应按场景/采集批次保留，近重复帧不能当独立样本。

**帧与耗时：**`VisionService.detect` 在 YOLO 和顶面定位全部完成后检查帧有效期；慢顶面测试证实过期结果报 `FRAME_EXPIRED`，同一 `request_id` 重试保留原失败，不生成新鲜坐标。D 取图仍按同一 `frame_id`。当前 YOLO 后端和顶面模块各解码一次相同 JPEG；为节约约 2 ms 修改两个后端的共享状态会扩大并发风险，本轮保留此行为。`top_face_ms` 包含顶面自身 JPEG 解码、颜色分割与几何处理；`inference_ms` 是模型后端总耗时，二者不等于纯模型计算。`captured_at` 是电脑收到并发布画面的时间，**不是板端曝光时间**，不保证网络传输没有积压。

**仍需实际采集：**真实偏紧 YOLO 框、顶面真正被遮挡、同色相邻或贴合、相似颜色背景、明显反光与阴影，以及新光照和静止目标连续帧。逐场景保存原图、分割图、前后对照和 JSON；确认完整顶面四角或标记不完整，再统计准确定位、主动拒绝及错误输出候选点。当前板端未连接，`--top-face` 实时 MJPEG 尚未实测。无真实相机标定与 B 的试抓数据，不能把像素误差换算成毫米或宣称可夹取。
