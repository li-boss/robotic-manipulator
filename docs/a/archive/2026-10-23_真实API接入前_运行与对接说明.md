## 3. C 检测接口与字段提案

`POST /api/v1/detect` 请求为 `{"request_id":"req-001","frame_id":"latest"}`，也可指定真实帧 ID。服务在首次处理时解析 `latest`；同一 `request_id` 的相同请求返回缓存的同一响应和同一实际帧，失败也缓存同一错误。恢复后重新检测必须换新 `request_id`。重复 ID 带不同 `frame_id` 返回 `BAD_REQUEST`。服务重启后缓存清空；跨重启幂等需 C 持久化或另行约定。

成功响应包含 `request_id`、实际 `frame_id`、`camera_id`、`captured_at`（Unix ms）、`image_width`、`image_height`、`coordinate_space=raw_camera`、`transform_version=raw-v1`、`outcome`、`targets`、`inference_ms`、`processing_ms`、`simulated`。目标含 `target_id`、`raw_label`、`category`、`confidence`、`bbox=[x1,y1,x2,y2]`、`center_x`、`center_y`、`target_status`。状态为 `ready`、`low_confidence`、`unmapped`；低置信度优先标注。`outcome=no_target` 表示正常推理但无目标。失败使用 `code,message,retryable,request_id`，例如 `FRAME_EXPIRED`、`CAMERA_UNAVAILABLE`、`MODEL_UNAVAILABLE`、`INFERENCE_FAILED`，不返回示例坐标。

现有 `contracts/README.md` 尚未定义 Schema。上面新增的帧、原始标签、状态和时间字段是交 C 的接口提案，需 C 维护的公共契约确认。`category=null` 或 `simulated=true` 的目标不得进入 B 动作请求。检测框中心仅是首版目标点，未经实机抓取验证。

## 4. D 图像接口与坐标

同一服务进程独占相机并缓存 JPEG，D 通过 HTTP 读取，不需要第二次打开设备。先 GET `/api/v1/frames/latest/meta` 获得 `frame_id`，再 GET `/api/v1/frames/{frame_id}` 获取同一帧 JPEG。元数据有采集时间、原始分辨率、相机 ID、坐标空间和编码；JPEG 响应头也给出 ID、时间、相机 ID。分辨率由实际输入决定；视频/摄像头默认最多约 10 帧/秒，静态图片 1 帧。默认缓存 32 帧，视频/摄像头帧有效期 500 ms（联调初值）。断流时 `latest` 报错，恢复后 ID 不复用。

对 D 提供**完整原图**，没有工作区裁剪。人脸是否在同一画面内取决于相机角度和安装位置；若不能同时看到桌面和人脸，团队需调整布局或增设相机。此接口只验证共享取图，不实现人脸识别。

当前流程的四个空间：摄像头原图 `raw_camera`；课程可能产生的透视校正工作区图（尚无算法/参数）；模型预处理输入图（真实模型尚无）；对外输出固定为原图。`ImageTransform` 能用实际裁剪、缩放、补边及逆透视矩阵还原坐标，不能仅按宽高比例推算。真实模型接入时必须用真实预处理参数填入；B 应用与 `raw_camera` 同一图像空间的标定。如果 B 需要校正图坐标，先由 C/B/A 明确修改契约版本。
