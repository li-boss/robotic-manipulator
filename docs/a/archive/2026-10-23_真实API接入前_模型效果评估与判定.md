## 第一关：20 张试标只验证流程

固定 `data/a_blocks/trial20_flow/data.yaml`（16 train、4 val），四张 val 均来自同一旧拍摄批次。此划分只用于命令和数据管线检查，任何 val 指标均不用于效果验收。流程通过须同时看到：

1. 类别文件与 `data.yaml` 的 ID 0–3 一致，训练和验证图片/标签全部正常加载，异常图或非法框为零。
2. YOLOv8n（`yolov8n.pt`）在 G 盘隔离环境完成 3–5 轮训练与验证，保存真实 `best.pt`、训练参数、依赖版本、日志和数据划分；色相、饱和度与亮度增强均关闭，特别禁止改变颜色类别含义的色相增强。
3. `best.pt` 能对至少一张原 JPG 做真实预测；保存模型原始标签、置信度、检测框、像素中心和叠加图。核实输出框是 **640×480 原图坐标**，结果可能是正常无目标，不能用 mock 坐标代替。
4. 试跑产生的权重、验证日志和预测文件可追溯；模型加载或推理失败须明确记录为失败。3–5 轮效果差不判定 YOLOv8n 不适合；4 张 val 指标高也不判定项目达标。

## 第二关：独立测试集评估识别效果

正式数据必须先按拍摄批次/场景/连续序列隔离近重复图片，训练、验证、测试三者不能交叉。独立测试批次在模型与阈值选择完成后**只评估一次**，不得反复据此选择模型。验证集用于选定置信度、IoU/NMS 阈值，然后锁定用于测试。

最终报告记录测试集图片数、各类别目标数、空场景数、类别顺序、数据和模型哈希、输入尺寸、置信度/NMS 阈值；逐类精确率、召回率、AP@0.5 与整体 mAP@0.5；单目标/多目标、中心/边缘、旋转、遮挡、光照分组表现。逐图保存成功、漏检、误检、错类、重复框及框偏移案例，并检查 raw_camera 原图框/中心。若任何类别明显漏检或定位不稳，即使整体 mAP 达到 0.75 也列为问题。没有足够的独立测试样本时结论只能是“证据不足，暂不能判断”。

当前需补拍并人工标注：无积木工作区；四种颜色分别在中心和四角/边缘；不同旋转、侧面朝向和轻度遮挡；两至四块相邻摆放；实际部署范围内较暗和较亮光照；至少一个**新拍摄批次**完整覆盖四种颜色和空场景。剩余 186 张可用于训练/验证候选，但不能默认是独立测试集。

## 第三关：速度与部署

记录模型加载时间、预热次数及稳定样本数量；逐图分别统计预处理、纯推理、后处理和 HTTP API 端到端耗时，报告均值与 P95。记录设备、运行时版本、模型哈希、输入尺寸、批量大小、置信度/NMS 阈值；GPU 测时需同步。`<=150 ms` 仅按**最终推理设备上稳定运行的纯模型推理**判断，电脑试跑速度单独列出。Atlas `.om` 转换、板端坐标和性能未验证时，部署结论保持“未验证”。

## 效果不足时的处理顺序

1. 检查漏标、错类、框是否统一、类别 ID 顺序。
2. 检查训练与推理预处理是否一致，缩放/补边/透视坐标还原及阈值配置是否正确。
3. 补充不足类别和失败场景的数据，训练集增强不得改变颜色标签含义。
4. 只在验证集上调整训练参数、置信度及 NMS 阈值，再用锁定方案测试。
5. 上述问题处理后 YOLOv8n 仍不足，才用同一数据划分、输入尺寸、阈值选择规则与测试协议对比 YOLOv8s，同时报告精度、延迟、显存/模型大小和 Atlas 可部署性。大模型不自动视为更适合。

对应建议只在证据支持时选择：继续使用 YOLOv8n、优先修正标注/补数据、对比 YOLOv8s、或先解决部署兼容性。当前建议是**继续 YOLOv8n 流程验证，并补独立测试数据**。

参考：[PyTorch 官方 Windows/CUDA 安装选择器](https://pytorch.org/get-started/locally/)、[Ultralytics YOLOv8 检测模型](https://docs.ultralytics.com/models/yolov8)、[Ultralytics 检测数据格式](https://docs.ultralytics.com/datasets/detect)。上述资料支持工具与格式选型，不等于已在本机或 Atlas 上跑通。

## 可执行评估入口与数据门槛

20 张试标的 16/4 划分只运行 `waste_vision.yolov8n_smoke`。若 G 盘隔离环境已安装训练依赖，可在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'G:\robotic-manipulator'
. .\tools\use-g-training.ps1
& 'data\a_blocks\.venv-train\Scripts\python.exe' -m waste_vision.yolov8n_smoke --device cpu --epochs 3 --output 'data\a_blocks\runs\yolov8n_smoke_01'
```

`--device cpu` 是明确选择的流程试跑，不代表 RTX 4060 或 Atlas 的速度。GPU 依赖就绪时改为 `--device 0` 并使用一个新输出目录。运行会拒绝覆盖已有目录；出现失败时保留日志并记录原因。真实 `best.pt` 和预测叠加图只证明流程与模型预测能运行，不能用于项目效果验收。

正式评估程序为 `waste_vision.model_effect_eval`。它需要人工审核并封存的独立测试清单 JSON。JSON 顶层必须有 `purpose: "independent_test"`、`sealed: true`、固定 `classes` 数组，以及 `splits.train/val/test` 三个非空数组。每张图的记录要有 `file`（对应分组下的文件名）、`capture_group`（同一批次/连续序列必须同组）、`image_sha256`、`label_sha256`、`scene_tags`、`empty_verified`。允许的场景标记是 `single`、`multi`、`center`、`edge`、`angle`、`occluded`、`dim`、`bright`、`empty`。空标签只有人工确认确实无积木后才能写 `empty_verified: true` 和 `empty`；未标注图片不能这样写。程序核验所有图片及标签、类顺序、哈希、同组跨集合和完全重复图片，并列出测试集中缺少的类别和场景。近重复仍需人工看图复核。

独立数据目录应采用 `images/train`、`images/val`、`images/test` 和对应的 `labels` 目录。`data.yaml` 的 `path` 必须指向同一数据目录，且明确列出 `train: images/train`、`val: images/val`、`test: images/test` 及四类顺序。阈值锁定 JSON 需由**验证集**选择后填写：`{"selected_on":"val","confidence":数值,"nms_iou":数值,"selection_notes":"选择依据"}`。程序拒绝缺少这些字段或覆盖已有评估目录。

数据准备好以后，先审查清单，再只对锁定的独立测试集运行评估：

```powershell
& 'data\a_blocks\.venv-train\Scripts\python.exe' -m waste_vision.model_effect_eval --dataset 'G:\robotic-manipulator\data\a_blocks\formal' --manifest 'G:\robotic-manipulator\data\a_blocks\formal\independent_manifest.json' --audit-only
& 'data\a_blocks\.venv-train\Scripts\python.exe' -m waste_vision.model_effect_eval --dataset 'G:\robotic-manipulator\data\a_blocks\formal' --manifest 'G:\robotic-manipulator\data\a_blocks\formal\independent_manifest.json' --data-yaml 'G:\robotic-manipulator\data\a_blocks\formal\data.yaml' --weights 'G:\robotic-manipulator\data\a_blocks\runs\正式训练目录\weights\best.pt' --threshold-lock 'G:\robotic-manipulator\data\a_blocks\formal\threshold_lock.json' --output 'G:\robotic-manipulator\data\a_blocks\evaluations\final_01' --device 0
```

第二条是**待正式数据和权重具备后**才可运行的命令模板，本轮没有执行。程序调用真实模型的 `val(split="test")`，以低置信度扫描计算整体 mAP@0.5 和逐类 AP；在**验证集锁定的操作阈值**下，将原图像素框按类别、置信度与 IoU≥0.5 一对一配对，另算逐类精确率和召回率。输出逐图原图像素框与中心、叠加图（黄色 `GT` 是人工真值框）、模型加载时间、预热后各阶段均值/P95。逐图 `review_required` 自动标记漏检、误检、错类或明显框偏移导致的配对失败；配对通过的框仍须人工看叠加图，检查定位可抓取性。API 端到端与板端速度另行实测，不能用本脚本的图片请求耗时替代。程序只给出“证据不足”或“需人工审核”，不会仅凭 mAP 自动写“足够”。
