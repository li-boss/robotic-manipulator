# 20 张积木图片：现在开始人工画框

## 已准备好的内容

试标目录是 `G:\robotic-manipulator\data\a_blocks\trial20`。其中 `images` 是从原有 `annotation_work` 复制的 20 张 JPG；`previews` 是供 Windows 自带 Tk 图形界面显示的 PNG 副本；`labels` 只存你亲手画出的 YOLO 标签。原始 `G:\新建文件夹 (2)\images` 和 206 张工作区图片都没有改动。试标图片、来源、哈希和尺寸记录在 `trial20\manifest.json`；选图理由见[试标20张清单](数据审查/试标20张清单.csv)，[联系表](数据审查/试标20张联系表.png)可先看全貌。

选图包含：蓝、红、黄、绿各两张单目标（共 8 张），另有 12 张双目标到四目标图片，覆盖相机画面不同位置、积木旋转和相邻摆放。没有选入数据审查列出的 8 对近似候选的双方组合。**这只是标注流程试跑，不是独立测试集。**

类别固定为：

| ID | 原始标签 | 判断依据 |
|---:|---|---|
| 0 | `block_blue` | 顶面蓝色 |
| 1 | `block_green` | 顶面绿色 |
| 2 | `block_red` | 顶面红色 |
| 3 | `block_yellow` | 顶面黄色 |

四种外观标签不代表四类垃圾；不要依据侧面图案或顶面颜色推断垃圾业务类别。

## 打开窗口并画第一张

标注窗口已经准备为只显示这 20 张图片，无需安装软件包。若窗口已由 Codex 打开，请找到标题 **“积木试标 20 张｜人工画框｜YOLO”** 并点击；第一张应显示 `1/20  193.jpg`。若窗口没有出现，在 **Windows PowerShell** 输入：

```powershell
cd G:\robotic-manipulator
py -3.10 -m waste_vision.trial20 gui
```

窗口左侧是 640×480 图片，右侧是类别、保存和切换按钮。每张图操作如下：

1. 看积木**顶面颜色**，点击右侧对应类别单选钮。也可按 `1` 蓝、`2` 绿、`3` 红、`4` 黄；旁边显示的 YOLO ID 仍分别为 0、1、2、3。
2. 在图片左侧按住**鼠标左键**，从整块积木可见外缘的一个角拖到对角。框住顶面和可见侧面，尽量贴合；不把阴影、地面十字或别的积木一起框进去。一个积木一个框，多目标依次选类别并画框。
3. 画错时，在错误框内**右键点击**删除，再重画。保存前核对每块积木都有框，框上的数字和文字与顶面颜色一致。
4. 点击 **“保存当前框 S”** 或按 `S`。标签写入 `trial20\labels\同名.txt`；右侧“已保存”应变成“是”。程序拒绝把没有框的试标图保存为空场景。
5. 点击 **“下一张 N”** 或按 `N`。上一张用 **“上一张 P”** 或按 `P`。若忘记保存，切换前会提示；请选择“否”返回保存。

若顶面颜色看不清，点击 **“切换待复核标记”**，再跳到下一张；不要猜类别，也不要建空标签。待复核文件记录在 `trial20\pending_review.json`。日后确认后回到该图，画框保存，再点击同一按钮解除待复核标记。

窗口保存的标签是每行 `class_id center_x center_y width height`，坐标按 640×480 图片归一化。已有标签重新打开时会显示已保存框；修改后保存会先在同目录保留 `.txt.bak`。这个试标目录独立于 206 张原工作区，不会覆盖其中任何标签。

## 20 张完成后如何检查

先不要在原 206 张目录运行“全部标好”检查。试标检查只针对这 20 张；其余 186 张单独记为未标，不当空场景。完成 20 张、解除所有待复核标记后，在 **Windows PowerShell** 运行：

```powershell
cd G:\robotic-manipulator
py -3.10 -m waste_vision.label_check --images data\a_blocks\trial20\images --labels data\a_blocks\trial20\labels --classes configs\a_confirmed_classes.txt
```

预期 `images=20`、`labeled_images=20`、`missing_labels=[]`、`problems=[]`、`ready_for_training=true`。这仅表示文件格式可用于下一步，**不证明框和类别正确**。把检查结果交给 A 模块；届时运行 `waste_vision.trial20_review`，生成逐张叠加图、联系表与试标检查报告，人工核对漏标、错类、框偏移及过大框。此脚本准备好了，但尚无人工标签，本轮没有伪造叠加图。

之后再安排剩余图片标注、空场景补拍及独立测试批次采集。20 张标注仅能用于小规模训练流程试跑，不能作为正式精度结论。训练会另建隔离环境；当前 A 的检测 API 和 mock 行为不变。
