## 3. 语音 WeNet 模型

`pc/voice_control/speech_recognition/wenet_asr.py` 硬性要求模型目录下有**四个文件**，缺一个就报 `缺少模型资源：…`：

```
final.pt      # PyTorch state_dict（非整模型对象，代码用 weights_only=True 加载）
train.yaml    # 训练配置：模型结构、cmvn_conf、tokenizer 类型
units.txt     # 词表，与 final.pt 必须配对
global_cmvn   # 倒谱均值方差归一化参数
```

目录默认是 `pc/voice_control/speech_recognition/models/wenet/`，也可用运行参数覆盖：

```powershell
& 'G:\venv-voice311\Scripts\python.exe' pc\run_voice_dance.py --model-dir D:\models\wenet
```

获取方式：由**语音模块负责人**提供的 WeNet 预训练导出版本（四个文件必须来自同一次导出，混用会导致 state_dict 键不匹配或识别乱码）。拿到后请补全本节表格里的 SHA-256。本机（2026-11-13）**尚未放置**该模型，所以语音链路只完成了代码合并，未做推理验证。

## 4. 为什么不把权重放进 Git

1. **体积**：合计约 60 MB（语音模型另有数十至数百 MB），每次 clone 都要付这份代价，而且仓库历史不可回收。
2. **二进制无法有效 diff/合并**：多人同时改权重必然冲突，冲突无法自动解决。
3. **分发场景不同**：权重按“谁需要谁拉”，用 Release 或局域网拷贝更合适。

## 5. 推荐的分发方式

**方式 A：GitHub Release（推荐，跨机器）**

1. 网页：仓库 → Releases → Draft a new release → 标签如 `weights-v1` → 把 4 个文件（`best.pt`、3 个 D 权重）作为附件上传 → Publish。
2. 别人下载后按第 2 节校验哈希即可。
3. 语音模型体量大（可能 >100 MB，超出单文件限制）时，用网盘/内网共享，只在 Release 说明里写链接与 SHA-256。

**方式 B：局域网直拷（现场最快）**

```powershell
# 在目标机器上执行，从 A 的机器直接拉
robocopy "\\<A机器名>\G$\robotic-manipulator-integration\pc\block_vision\weights" `
         "G:\robotic-manipulator-integration\pc\block_vision\weights" best.pt /NFL /NDL
```

**方式 C：不要做的**：`git add -f` 强推权重进 main。会让仓库永久膨胀，且后续每次 clone 都慢。
