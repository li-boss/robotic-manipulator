# 生产入口选边与候选对称性离线排查

日期：2026-11-13。全程电脑离线；未访问设备HTTP/SSH、未部署、未发送运动。
复用已确认的`edge_one`人工标注。新增合成规划对照，没有把合成参数当作现场数据。

**发现并修复可复现缺陷：相邻等价方向的浮点误差会使解析腕部初值略低于90°，
在候选生成阶段丢失合法分支。合成230毫米案例因此出现“选左边拒绝、选上边通过”。**
该现象与现场报错文字相同，但尚无现场失败请求证明现场由同一缺陷触发。

## 1. 三条实际生产路径

| 入口 | center_px | edge_px | outline_px |

| `/manipulation`人工拖框 | 操作者另点顶面中心，或显式输入坐标；不是框中心自动生成 | 操作者另点同一条边的A、B两点，或显式输入 | 拖框时删除，不发送 |

## 3. 方向等价性在规划中的处理

### 反转180°与换边90°

`edge_px`反转会使投影方向反转180°。
如果邻边投影后恰好正交，换邻边会改变基坐标yaw ±90°。
若四角误差/投影使邻边不是精确正交，则方向族会有真实的小角差，不能强行当成完全等价。

- 快速候选：`board/manipulation_ik.py:105`显式枚举`yaw+(0,90,180,270)`。
  理想数学上，yaw加90°或180°只重排这四个方向，不改变方向集合。
- 每个方向分别构造解析根、枚举绕转、检查配置范围、做短程数值修正和整数化。
  `board/manipulation_ik.py:114`是解析根的严格范围筛选；后续仍检查物理范围、位置误差、
  `max_direction_error_deg`以及接近轴误差≤0.035，再以整数关节组去重。
- 非九点慢速逆解：`board/manipulation_geometry.py:516`也枚举四个方向，严格FK与方向误差筛选后选最优解。
- 九点引导：`board/manipulation_guided.py:19`枚举倾角，`:28`的options调用完整四方向候选生成器。
- 快速预检：`:68`的`grasp_endpoints()`遍历各倾角生成的候选，`:76`检查碰撞，`:79`检查夹持中心高度；
  抓放任务还检查放置可行性。`:87`的`precheck_grasp()`找到一个通过终点即放行预检，
  没有通过终点就拒绝；它不会重新使用另一套搜索补齐已被候选生成器丢失的分支。
- 后续完整搜索`:138`的`move()`继续调用相同候选和碰撞/扫掠检查。
- 电脑计划板端复核：`board/manipulation_replay.py:144`～`:145`按四方向最小误差复核夹爪方向，
  并继续检查位置、姿态、碰撞和路径。

因此代码意图覆盖等价方向，但有限数值算法不自动保证枚举出来的整数姿态集合完全一致。
本轮复现的是解析初值的浮点边界问题，不是少写了90°或180°的枚举。

### 初值丢失的具体数值

左边投影yaw约`-89.99999999999996°`，加90°后相对方向正弦约`7.32494e-16`。
解析腕部初值算出`89.99999999999996°`，比配置下界90°低`4.26326e-14°`。
该根的其余四关节均在范围内，却在`candidates()`的严格初值范围判断中整体被丢弃，
因此根本没有进入整数90°/91°候选的FK验证。
上边投影yaw为0°时，等价分支初值为90°，能够进入下一阶段。

详细数值见修复前`analytic_seed_trace_230mm.json`，包括另一个本来就非法的肘部分支；
没有把那个分支当作有效根。

## 6. 结论与现场边界

1. **存在可复现的入口选边差异：**8099取模型第1→2角；人工四角取用户第1→2次点击。
   本次四角顺序套入页面规则时，上边与左边不同；人工拖框历史选哪条边仍未知。
2. **现有合成条件下，选边确实能改变修复前的预检结果。**原因是解析初值舍入导致合法候选丢失，
   已最小修复并以完全相同输入验证；无需调整HSV或碰撞条件。
3. **原230毫米现场是否为同一原因仍未证实。**缺原失败请求、同帧读数/配置、部署版本，
   也没有证明人工成功和8099失败同帧同目标。真实投影后若相邻边并非精确90°，仍可能产生真实候选差异，
   不能用本合成测试代替现场结论。
4. 本轮没有部署。规划代码指纹已变化，后续使用电脑规划时两端须保持同版本并通过原板端复核。
