## 1. 整体是怎么连的

```
┌──────────────── 电脑（你们的模型跑在这里）────────────────┐        ┌────────── 开发板（机械臂控制）──────────┐
│                                                           │  网线  │                                         │
│  pc/run_block_grasp.py ─┐                                 │ HTTP   │  board/server.py  (192.168.137.100:8080)│
│     你的 BlockDetector  │──→ pc/armlink/BoardClient ──────┼───────→│   /api/v1/*  ← 只收“图里方块在哪”       │
│  pc/run_gesture_dance.py┘       （标准库 urllib）         │        │             ← 或“跳哪一套舞”            │
│     你的 GestureRecognizer                                │        │  定位 + 逆解 + 路径碰撞检查 + 统一舵机校验 │
│                                                           │        │  摄像头 /dev/video0、舵机 Arm_Lib       │
└───────────────────────────────────────────────────────────┘        └─────────────────────────────────────────┘
```

- **开发板**只有 NPU，跑不了 PyTorch，所以模型都在电脑上跑；开发板负责摄像头、定位、规划和舵机。
- 电脑和开发板用网线直连：开发板 `192.168.137.100`，电脑有线网卡设成 `192.168.137.101 / 255.255.255.0`。
- 电脑端识别程序**只发识别结果**（像素坐标、手势标签），**不发关节角度**。
- 另有一个可选的**电脑端规划服务** `pc/plan_server.py`：开发板把抓放的逆解和路径搜索交给电脑算（快几倍），但电脑算出的关节指令只是候选，开发板会自己逐段重放复核，不通过就丢弃、改用开发板本地计算。详见第 7.1 节。

### 运动授权（必须知道）

机械臂不会因为电脑端发了个请求就动。流程是：

1. 有人在网页 `http://192.168.137.100:8080/modes` 选模式 → **预览**（页面列出本次全部限制和动作参数）→ 勾选确认 → **开启模式**。
2. 开启后才有一个“会话”（`session_id`），电脑端的请求必须带上它。会话有次数上限和有效期。
3. 超时、次数用完、任一动作失败、网页点“关闭模式”、电脑端 Ctrl+C（会发 `/api/v1/stop`）都会立刻结束会话。
4. 关闭只停止**后续**动作，已发给舵机的指令撤不回来，网页不是急停。现场一定要有人看着。

这是项目规则 [AGENTS.md](../AGENTS.md) 和 [机械臂操作准则.md](../机械臂操作准则.md) 里“网页开启识别模式授权”一节的要求，代码里也是这么强制的，别想办法绕过。

## 4. 方块识别同学

### 4.1 你要写的东西

在 `pc/block_vision/` 新建一个文件，例如 `yolo_detector.py`：

```python
from armlink import BlockDetection
from block_vision.base import BlockDetector


class YoloBlockDetector(BlockDetector):
    def __init__(self):
        import torch
        self.model = torch.hub.load(...)          # 模型只在这里加载一次

    def detect(self, image):                      # image: BGR, uint8, H×W×3（开发板原图，目前 640×480）
        results = []
        for det in self.model(image):             # 伪代码：换成你的推理
            results.append(BlockDetection(
                corners=det.top_face_corners,      # 顶面 4 个角，原图像素 [[u,v],...]，沿轮廓顺序
                score=det.confidence,              # 0~1
                label=det.class_name))             # 可选，只用于日志
        return results                             # 没有方块就返回 []
```

运行：

```bash
python pc/run_block_grasp.py --detector block_vision.yolo_detector:YoloBlockDetector
```

`--detector` 的格式是 `模块:类名`，模块要能从 `pc/` 目录 import。

### 4.2 输出格式（`BlockDetection`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `corners` | 二选一（推荐） | **顶面**四个角点 `[[u,v]×4]`，沿轮廓顺序（顺时针或逆时针都行）。**第 1→第 2 个角那条边**决定夹爪方向。 |
| `bbox` | 二选一 | `[left, top, right, bottom]`。只有框没有角点时用。 |
| `angle_deg` | 否 | 配合 `bbox`：顶面一条边在图里的角度（度，0=水平向右，顺时针为正）。不给按 0。 |
| `center` | 否 | 顶面中心 `[u,v]`。不给时：`corners` 取两条对角线交点，`bbox` 取框中心。 |
| `score` | 否 | 置信度 0～1，默认 1。低于网页设置的下限会被拒绝。 |
| `label` | 否 | 类别名，只记录日志。 |

**一定注意：**

1. 坐标必须是**开发板原图**的像素（原点左上角，u 向右，v 向下）。如果你把图缩放到 416×416 推理，要把坐标**换算回原图**再输出。
2. 要的是**顶面**，不是整个方块的轮廓。相机是斜着看的，方块侧面也会露出来；把侧面算进去，定位会偏。这也是为什么示例颜色检测器只适合俯视——它分不出顶面和侧面。最好让模型直接输出顶面四角（例如关键点检测、或分割后取顶面多边形）。
3. 当前只支持 30×30×30 mm 的方块，静止、平放、不堆叠。
4. 一次返回多个也没关系，运行器取 `score` 最高的那个。

### 4.3 每次抓取发生了什么

1. 电脑端 `POST /api/v1/block/frame`：开发板**冻结一帧**，同时读取六关节真实角度（机械臂必须停稳）。返回 JPEG 图像。
2. 你的 `detect()` 在这张冻结图上找方块。
3. 电脑端 `POST /api/v1/block/target`：把结果连同 `frame_id` 发回。开发板用**冻结时的关节角**算出相机位姿 → 把像素投到桌面 → 逆解 → 完整路径碰撞检查 → 自动执行。这一步可能要几秒到几十秒（开发板算力有限）。
4. 等任务结束，再从第 1 步开始下一次。

所以：**检测结果必须对应同一个 `frame_id` 的那张图**，不能拿别的时刻、别的分辨率的图去检测然后套这个编号。冻结后 120 秒内有效。

### 4.4 收集训练数据

开发板摄像头的视角和你电脑摄像头不一样，建议直接用开发板的图训练：

```bash
python pc/run_block_grasp.py --save-frames data_frames/
```

（需要先在网页开启模式；每次冻结的原图都会存下来。）也可以不开模式，直接反复拿实时快照：

```python
from armlink import BoardClient
open('x.jpg', 'wb').write(BoardClient().snapshot())
```

### 4.5 常见拒绝原因（开发板返回的中文提示）

| 提示 | 原因 |
|---|---|
| 模式未开启 | 网页还没开启“方块识别自动抓取” |
| 检测置信度低于本会话下限 | `score` 太低 |
| 中心和方向端点必须位于目标框内 / 顶面四角…不能交叉或共线 | 角点乱序或退化，检查 corners 顺序 |
| 方块边缘超出已核对桌面区域 | 方块不在机械臂工作区里 |
| …超出模型水平伸展范围 / 路径碰撞 | 机械臂够不到或会撞，换个位置 |
| 有操作正在执行 | 上一个动作没结束（运行器会自动等） |

规划失败不会让机械臂动；连续 5 次规划失败会自动结束会话。

## 5. 表情手势同学

### 5.1 你要写的东西

在 `pc/gesture/` 新建，例如 `mediapipe_gesture.py`：

```python
from armlink import GestureEvent
from gesture.base import GestureRecognizer


class MediapipeRecognizer(GestureRecognizer):
    def __init__(self):
        import mediapipe as mp
        self.hands = mp.solutions.hands.Hands()

    def recognize(self, image):                # BGR 图像（电脑摄像头或开发板摄像头）
        label, conf = my_classify(image)       # 你的模型
        if label is None:
            return None                        # 这一帧没有约定的手势/表情
        return GestureEvent(label=label, confidence=conf)   # label 自己定，如 'smile' / 'wave'

    def close(self):
        self.hands.close()
```

运行：

```bash
python pc/run_gesture_dance.py --recognizer gesture.mediapipe_gesture:MediapipeRecognizer --source webcam --map smile=course,wave=circle
```

- `--source`：`board`（开发板摄像头，当前手势模型默认）、`webcam`（电脑摄像头）、`webcam1`（第二个摄像头）、`none`（不取图，配合键盘模拟）。
- `--map`：你的标签 → 跳舞动作。目前有两套动作：`circle` 画圈（1 号 + 4 号走一圈）、`course` 课程舞蹈（课程资料《任务7：机械臂跳舞》那支舞，逐拍照录）。网页首页的“跳舞预设”卡片可以直接点按钮试跳同样的动作。
- `--stable 3 --threshold 0.6`：同一标签连续 3 帧且置信度 ≥ 0.6 才算一次触发；触发后要先看到别的结果（或没有手势）才会再次触发，防止一直跳。

你只管“这一帧是什么”；取帧、防抖、冷却、发请求、等跳完，运行器都做了。

### 5.2 跳舞动作是怎么来的

- 起点：网页开启模式时选的“姿态按钮”（在首页保存的六关节姿态）。
- 动作：`board/data/dances.json` 里的模板，例如 `course` = 课程资料里的那支舞，17 拍，从“竖直”（六个关节都是 90°）出发。每套动作先逐关节到起点，再一拍一拍摆。
- 所有角度都会在开启时算好、显示在网页上让人确认；任何一个超出关节范围就整套拒绝（不会自动截断）。
- 想要新动作（比如挥手），在 `board/dance.py` 的 `offsets()` 里加一个模板，再在 `dances.json` 里加一项——这属于开发板端改动，请和机械臂控制同学一起改并跑测试。

## 6. 语音控制

`pc/speech_recognition/` 用 WeNet 将一段 WAV 转为文字，`pc/voice_control/commands.py` 的 `parse_command()` 只匹配“机械臂画圈”→ `circle`、“机械臂跳课程舞”→ `course`。未匹配的文字不连接开发板。`pc/run_voice_dance.py` 支持 `--wav` 或 `--mic`（两次回车开始/结束录音），每次运行最多提交一个动作，固定在 CPU 上推理。

现场人员先在开发板 `/modes` 页面预览并开启 `gesture_dance` 会话，选中对应动作。程序读 `BoardClient.mode()`，核对会话和授权动作，再调用 `BoardClient.dance()` 并等待任务结果；开发板仍负责次数、冷却、去重、运动检查。默认 `--board http://127.0.0.1:8092` 指向本机模拟服务；实机地址须显式传入。没有额外语音模式或关节控制接口。

## 7. HTTP 接口参考（`/api/v1`）

基地址 `http://192.168.137.100:8080`（模拟时 `http://127.0.0.1:8092`）。请求体都是 JSON，`Content-Type: application/json`。失败时 HTTP 400/503，响应 `{"error": "中文原因"}`。`pc/armlink/client.py` 已经封装好，一般不用手写。

| 方法 路径 | 作用 | 会不会动 |
|---|---|---|
| `GET /api/v1/health` | `{service, api_version:1, mode:"real"/"simulation", camera:{connected,...}, busy}` | 不动 |
| `GET /api/v1/mode` | 当前会话：`{armed, kind, session_id, used, max_actions, expires_in, busy, message}`；跳舞另有 `routines, cooldown_s`，抓取另有 `task_mode, min_score` | 不动 |
| `GET /api/v1/job` | 最近任务：`{busy, job:{id, status, sent, total, message, error}}`，status = `running/completed/failed/stopped` | 不动 |
| `GET /api/v1/frame.jpg` | 开发板摄像头最新一帧 JPEG（不冻结、不读舵机） | 不动 |
| `POST /api/v1/block/frame` | `{session_id}` → `{frame_id, image_size, captured_at, joints, jpeg_base64}`。冻结一帧并读六关节 | 不动 |
| `POST /api/v1/block/target` | `{session_id, frame_id, detection:{corners|bbox, angle_deg?, center?, score?, label?}}` → `{job:{id,status}, target:{xyz_mm, edge_yaw_deg, destination_xy_mm, ...}, steps, warnings, used}` | **会动**（会话已授权） |
| `POST /api/v1/gesture` | `{session_id, routine, request_id(32位十六进制), label?, confidence?}` → `{job:{id,status,total}, routine, duration_ms, used}`；同一 `request_id` 重发只返回原任务，不会跳两次 | **会动**（会话已授权） |
| `POST /api/v1/stop` | `{session_id?}` 结束当前会话 | 停止后续动作 |

用 curl 看状态：

```bash
curl http://192.168.137.100:8080/api/v1/mode
```

网页自己用的接口（`/control/*`、`/manipulation/*`、`/modes/*`、`/calibration/*`）要求同源和页面令牌，电脑端程序不要调用。

### 7.1 电脑端规划服务（让“生成计划”变快，可选）

开发板只有 3 个可用 CPU 核，一次抓放规划要十几秒。连接机械臂的那台电脑开着下面这个程序时，开发板会把计算交给电脑：

```bash
python pc/plan_server.py
```

- **需要的环境**：Python 3.9+，`pip install -r pc/requirements.txt`（就是 numpy 和 opencv-python），再加上项目里的 `board/` 目录（规划代码在那里）。不需要 ROS、PyTorch，也不需要 Linux。电脑上不保存任何现场数据，换哪台电脑都一样。
- **Mac**：双击项目根目录的 `启动电脑端规划.command`（第一次会自动建 `.venv-mac` 并装依赖）；`启动机械臂网页.command` 也会在启动网页后接着运行它。
- **怎么连**：开发板默认找 `http://192.168.137.101:8095`。第一次在 Windows 上运行时，防火墙会弹窗，允许“专用网络/公用网络”访问（网线直连通常被识别为公用网络）。
- **版本**：电脑和开发板的规划代码必须是同一版本（自动比对指纹，换行符差异不算）。不一致时开发板自动用本地计算，网页计划里会写原因。
- **安全**：电脑只返回各阶段的关节指令。开发板用自己的配置和标定重放复核：角度范围、每段终点位置和方向、每段同步运动和发送滞后的碰撞扫掠、夹持与放置。任何一项不过就丢弃电脑结果。确认、模式授权、执行流程和安全规则都不变。
- **没开也没关系**：电脑没开或连不上时，开发板自动本地计算，功能不变，只是慢。网页“计划”摘要里的“计算来源”会写明这次是谁算的。
- **本地联调**：

```bash
python pc/plan_server.py --host 127.0.0.1
```

```bash
python board/simulate.py --pc-planner http://127.0.0.1:8095
```

  模拟器会接入一套合成九点参考（只用于测试），抓取计划摘要应显示“电脑端计算 + 开发板逐段复核”。

## 8. 怎么合并（git 协作建议）

项目以前没有用 git，建议现在建一个仓库（机械臂控制同学负责）：

```bash
git init && git add . && git commit -m "重构后的基线"
```

`.gitignore` 已经排除了虚拟环境、设备运行记录等。之后：

1. 每人一个分支：`feat/block-vision`、`feat/gesture`、`feat/voice`。
2. 只在自己的目录加文件：`pc/block_vision/xxx.py` 或 `pc/gesture/xxx.py`；模型权重太大的不要提交，放网盘，在代码里写好路径和下载说明。
3. 新依赖写进 `pc/requirements.txt`（或你自己的 `pc/block_vision/requirements.txt`）。**开发板端不要加依赖**，开发板装不了 PyTorch。
4. 合并前跑一遍全部测试（不连硬件）：

```bash
zsh tools/run_tests.sh
```

5. 最好给你的检测器/识别器加一个小测试放在 `pc/tests/`，例如喂一张已知图片，检查输出格式（四个角、坐标在图内、score 在 0～1）。
