# 机械臂操作行为准则

当前 pickup_only 自动抓取按用户最新要求使用本次人工确认的冻结识别中心与完整计划，确认后不重新读取相机或检查其他有色目标；执行前核对冻结中心、计划与原映射一致。用户当次确认中心正确且方块位置未移动。保留目标边界、版本、去重、硬件锁、已有读数策略及下发异常停止；此要求不授予助手自行运动的权限，旧逐步验证仍按原实时检查。

## 自动抓取读取失败例外（用户2026年10月4日明确要求）

当前 pickup_only 自动识别抓取在预览、执行前及运动后发生读数失败时，记录失败和警告后继续本次已确认的有限计划，不重读、不伪造读数、不自动重试运动或返回。起始读数缺失时使用用户当次勾选的固定观察姿态、夹爪张开确认；预期关节目标与实际回读分别记录。成功读取但姿态不符或超范围、下发异常、非法参数和版本变化仍停止。真实示教资料记录与旧程序验证不适用此例外，缺失读数不得写成到位或验证成功证据。此条优先于下方一般失败读数拒绝及异常停止描述，仅限读取失败，不改变运动授权要求。

适用于本项目今后所有控制脚本、临时命令、Notebook 和 ROS 控制节点。现有课程资料作为参考，不因其中有示例代码就允许直接执行。

## 1. 运动前必须取得当次同意

在设备 `192.168.137.100` 上执行会引起机械臂运动的操作前，助手必须说明操作内容并取得用户当次明确同意，运动重试也不例外。基础指令、环境检查、源码读取、文件部署及经审查不触发运动的角度读取可直接进行。扭矩切换、动作组回放等可能导致位移的操作同样需要确认。一次运动授权只覆盖说明过的当次操作或明确列出的有限批次。

运动前应列出：脚本/命令、实机或模拟模式、涉及的关节与目标角度、运动用时、动作次数或步骤、起始条件和停止方式。参数或脚本变更后重新确认。SSH 密钥登录和 `hardware_ready=true` 都不能替代批准。

本地编写文档、修改代码及不连接设备的测试不属于实机操作。

每次运行脚本前，重新核对 `AGENTS.md`、本准则、实际执行代码及参数，向用户说明合规检查结果；涉及运动时等待当次确认，基础操作无需逐次确认。设备端所有项目代码、配置、测试与日志统一放在 `jjt` 目录；已确定使用 `/root/jjt`。覆盖已有文件前检查内容并保留用户修改。系统现有依赖不迁移，本地文件可作为审阅或同步副本。

## 2. 角度的数值硬限制

角度单位统一为度，表示绝对目标角度。所有边界均包含端点。

| 舵机 ID | 单关节变量 / 多关节变量 | 不可突破的代码硬边界 |
| --- | --- | --- |
| 1 | `angle`（id=1）、`s1`、`p[0]` | `0 <= angle <= 180` |
| 2 | `angle`（id=2）、`s2`、`p[1]` | `0 <= angle <= 180` |
| 3 | `angle`（id=3）、`s3`、`p[2]` | `0 <= angle <= 180` |
| 4 | `angle`（id=4）、`s4`、`p[3]` | `0 <= angle <= 180` |
| 5 | `angle`（id=5）、`s5`、`p[4]` | `90 <= angle <= 270` |
| 6（夹爪） | `angle`（id=6）、`s6`、`gripper.open`、`gripper.closed` | `0 <= angle <= 180` |

依据：本地第二阶段任务1及任务4。任务4中5号舵机同时出现 `0～270°` 与 `90～270°` 两种说明，本项目取两者交集 `90～270°`。这些是基于所给资料设定的项目限制，尚未通过实机核验，不是厂家安全认证，也不是建议运行到极限位置。

每个关节还必须填写实机核对后的 `joint_limits["id"]=[lower, upper]`：

- ID 1、2、3、4、6：`0 <= lower <= upper <= 180`。
- ID 5：`90 <= lower <= upper <= 270`。
- 目标同时满足 `lower <= angle <= upper`，否则拒绝。
- 上下界和运动目标均为整数值；拒绝布尔值、字符串、空值、NaN、无穷和非整数角度。
- `joint_limits` 未配置时禁止对应关节运动。不得用硬边界自动补全，更不能把未核对的整个硬边界称作实机安全范围。

不得静默截断、取模或把非法角度修改成邻近合法值后执行。未来逆运动学输出须先显式转换单位，再走同一校验。

2026年10月2日经用户确认：起始读数允许在已核对配置区间边缘存在1°观察偏差，例如5号目标90°回读89°。校验观察使用独立入口并原样保留读数，不把89°转换为90°，不据此自动修正运动。运动目标及配置仍须严格满足上表硬边界。超出容差、无效或失败读数继续拒绝；姿态记录含非法目标时须人工核对明确的目标值，禁止自动补1°或截断。

## 3. 其余变量与姿态限制

| 变量 | 强制约束 |
| --- | --- |
| `id` | 整数 1～6，拒绝布尔值 |
| `p` / `poses.*` / `targets.*.above` / `targets.*.drop` | 恰好5个角度，按 ID 1～5逐项校验 |
| 六关节接口的 `s1...s6` | 恰好6个角度，分别按六个关节范围校验 |
| `gripper.open`、`gripper.closed` | 按 ID 6校验，必须来自实际夹爪调试；不预设开合方向或夹持角度 |
| `motion_ms` / 硬件写入的 `time` / `s_time` | 整数 `500～10000 ms`，默认 `1500 ms`，禁止 `0` |
| `settle_ms` | 整数 `100～5000 ms`，默认 `300 ms` |
| `hardware_ready` | 初始为 `false`；只有完成实机条件核对才可显式设为 `true` |
| 自动重试次数 | `0`，故障后重新审批再操作 |
| 同时执行的硬件控制任务数 | 最大 `1` |

时间范围是本项目的软件运行约束，不是声称设备支持的完整规格。后续脚本改变这些限制前，必须修改准则、补测试并向用户说明，不能自行放宽。

没有实测依据时，不预设所有关节通用的安全单步角差、桌面高度、负载、转移高度或安全初始姿态。当前相关姿态保持 `null`，完成记录和路径验证后才启用。角度合法仅是必要条件，无法保证连杆不会碰撞桌面、其他连杆或拉扯线缆。

## 4. 下发、异常及示教规则

1. 完整任务先检查全部目标参数；每批指令在第一条写入前再次验证该批所有关节，任何一个非法都不得部分执行。
2. 所有硬件写入都通过控制层统一校验，不得使用临时 Python 片段、直接串口、六舵机接口或存储动作组绕过限制。
3. 读取角度失败时报告错误，不用 `0` 或模拟读数补齐；读取结果仅用于观察，不能自动触发纠正动作。
4. 初次验证路径采用空载、逐步执行；姿态记录成功不等于路径安全。单次运行默认有限步骤，不自动无限循环。
5. 故障或用户中止时停止后续下发，禁止在异常处理或 `finally` 中自动回零、松爪或复位。已发出的运动可能继续，使用经实机确认的停止方式。
6. 扭矩关闭可能导致机械臂下落；切换学习模式、回放动作组、改变舵机 ID 或校准参数均需独立审查与批准。禁止强掰带扭矩关节，不自动清空已有动作组。
7. 本项目的进程锁不能约束其他 Notebook、其他项目副本或外部程序；上机前确保只有一个控制来源。

## 5. 合规验证

新增或修改控制代码时，至少验证：六个关节的边界内外输入、配置扩大硬范围、非法数值、整批预检、未就绪硬件拒绝下发，以及异常后无后续指令。测试使用假设备，禁止连接真实硬件。

本准则不授权未经当次确认的实机运动；基础操作按第1节执行。当前未核实设备的实际安全姿态、停止接口和各关节工作范围，保持实机动作禁用。


## 网页手动调整简化（按用户本次要求）

单关节手动调整时，页面展示关节、角度和用时；输入角度后回车或点击该行“确定”，就是对该次明确参数的运动确认，无需再次预览或勾选。手动调整不要求先读齐六关节，也不以回读成功作为下发前提。目标仍经过配置范围、整数、时间及控制层校验，保留硬件锁、请求去重、审计和异常不重试。拍照示教及自动完整任务保留其必要的姿态读取和计划确认。助手不得因这项界面授权自行发送实机运动。


## 用户明确保存的网页六关节姿态按钮

按用户要求，六个目标角度、各一次的六关节顺序及每关节用时先分析并保存。页面卡片展示该有限六步计划及实机/模拟模式，用户点击“确认依次调整到”即当次授权这份明确计划，无需第二个确认框，也不要求先读齐六关节。每一步通过Controller.write逐关节执行并等待既定用时与停稳时间；整批预检、硬件锁、版本核对、请求去重和异常停止后续下发仍适用。该按钮使用项目文件中的明确目标，不回放设备存储动作组、不切换扭矩。保存不证明实机姿态或路径已验证；实际拍照标定独立检查姿态，不自动拍照或计为验证证据。助手不因此获得自行触发按钮或实机六步运动的授权。


## 人工标注随臂定位与整批执行（用户2026年10月23日最新要求）

新的人工目标CAD模式（`capture_mode=joint_snapshot_v1`）使用每张冻结画面的完整真实六关节读数，不要求固定观察姿态或预先张开夹爪。标注后直接生成完整有限计划，张开夹爪列入本次确认动作；起始夹爪必须空载。该模式不以五个位置的空载验收或事先独立采用模型候选作为整批执行前提，模型、成像参数来源、实际起始读数及全部运动参数随本次计划一起展示。用户点击“确认执行以上步骤”即当次授权；不得在生成或标注时自动下发，也不授权助手替用户点击实机执行。空载逐步验证保留为可选操作，未做实测仍如实标记未验收。

此条为上述首次路径强制空载规则在本模式下的明确例外。其他入口、旧pickup_only读取例外保持原范围。真实完整读数、起始姿态与冻结/预览一致性、合法整数目标与配置范围、全路径碰撞和扫掠、硬件锁、版本与去重、异常后停止且不自动重试/复位/松爪仍适用。原始读数只用于投影和路径起点，不截断或修改成运动目标；完整抓放在放置后撤离，不自动返回由读数构造的姿态。


## 人工标注抓放读数失败与同步运动（用户2026年10月29日明确要求）

适用于人工目标CAD随臂模式（`capture_mode=joint_snapshot_v1`）的完整抓放计划：

1. 预览一致性复核、执行前起始读取和每步运动后读取时，个别关节读取失败只记录真实错误与警告并继续本次已确认计划，不重读、不补造读数，该步不计为已验证。冻结采样仍须六关节完整读数。
2. 成功读取的关节与冻结/预览起点或本步目标相差超过1°时停止。夹持方块后到释放前，6号读数介于张开值与夹持目标之间（各含1°）视为被方块阻挡，记录警告继续。
3. 同一阶段需要变化的关节合并成一次 `Controller.write` 批量指令（同一运动用时，按关节编号约20 ms间隔依次发出），张开夹爪并入第一段移动。规划须检查同步线性插值和发送滞后包络两条采样路径的完整碰撞与扫掠；不通过时依次退回经模型零点的同步路径、原逐关节路径。
4. 空载逐步验证、旧照片/角度示教不适用本例外。本条不改变运动授权：仍须用户在网页当次确认，助手不得自行触发。


## 人工标注抓放即时执行、回读容差与桌面高度来源（用户2026年10月29日第二次明确要求）

1. 用户在网页确认执行后，不再重复完整计划计算；以服务端保存的预览计划为准，核对其输入指纹（抓放配置、机械臂配置、冻结目标、九点参考）及规则、代码、证据审计散列一致后立即进入执行前读数和下发。整批目标与时间预检、硬件锁、去重和异常停止不变。
2. 随臂完整抓放计划每步运动后，成功读取关节与本步目标相差不超过3°时记录警告并继续，该步不计为验证；超过3°停止。起始姿态与冻结/预览的一致性仍为1°。空载逐步验证和其他入口仍为1°。
3. 桌面高度可采用手眼标定的标定板平面估计（四角平均高度减去纸与底板厚度，本次用户说明贴硬纸板，按3毫米）。板面四角高差上限为10毫米并记录实际值；原安装板80毫米实测来源保留为历史记录，不再参与定位。采用参数不运动，也不代表抓取精度已验收。


## 人工标注抓放混合高度与运输段衔接（用户2026年10月29日第三次明确要求）

1. 运动目标、碰撞与扫掠使用安装板80毫米实测桌面基准；图像像素换算平面坐标使用手眼标定板面高度（板面四角平均减3毫米板厚，四角高差上限10毫米），换算后高度取实测基准。该投影来源随手眼结果核对，内参或手眼变更即失效。
2. 相邻移动段可提前下发衔接：上一段结束前按计划给出的提前量下发下一段，中间不停稳、不读取。规划须检查切角路径（按多个提前比例及发送滞后包络采样）；不通过则该处保持停稳回读。夹持、释放前后及最终一步仍停稳回读，衔接段不计为验证。
3. `Controller.write` 新增的等待时长参数只能缩短本批写入后的等待（0至用时+停稳之间的整数毫秒），角度与时间校验、实机就绪检查不变。


## 任意观察视角：单帧方块尺寸自校与可达提示（用户2026年10月29日第四次明确要求）

1. 随臂模式且有四角顶面标注时，每帧以已知方块边长求解投影平面修正，四边须在已知边长±15%内、修正量与手眼板面差≤40毫米，否则退回手眼板面并警告；修正只用于像素换算，运动高度用实测基准。
2. 规划前检查取放点是否超出模型水平伸展上限（未计碰撞），超出则说明原因并拒绝；取放方向不兼容时明确提示。画面上的可达范围仅供参考。


## 网页运动写入失败自动重发（用户2026年10月30日明确要求）

1. 适用于网页人工抓放计划、单关节手动调整和六关节姿态按钮：单个关节 `Arm_serial_servo_write` 失败时，间隔约30毫秒重发同一绝对角度与用时，最多2次，并逐次记录；仍失败则停止后续下发。
2. 只重发同一条已校验指令，不修改目标、不插入其他动作、不复位或松爪。`Controller.write` 的重发次数参数默认0，其他入口不变。
