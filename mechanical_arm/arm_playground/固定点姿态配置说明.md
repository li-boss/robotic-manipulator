# 固定取物点与黄色区域配置

本阶段已经确认供电开关开启后通信恢复，用户报告六关节测试完成。单关节测试完成并不等于多关节抓放路径已安全验证。所有运动仍按项目操作准则逐次批准。

## 当前工作

固定相机、取物标记和黄色放置区域，空载记录以下姿态；记录工具只读取并保存，不会移动机械臂。

| 名称 | 记录时机械臂所在位置 |
| --- | --- |
| ready | 核对过的空载准备位置 |
| pickup_above | 固定取物标记上方 |
| pickup | 固定取物标记的抓取位置 |
| targets.yellow.above | 黄色放置区域上方 |
| targets.yellow.drop | 黄色区域的放置位置 |
| gripper.open | 经观察确认张开的夹爪 |
| gripper.closed | 经实际夹持调试确认的夹爪角度 |

准备姿态、上方高度、夹爪开合角度都没有通用默认值。不同名称需对应不同实测位置，不要将下面的记录命令直接连续执行。不得强掰带扭矩关节，也不要使用未经批准的学习/扭矩切换方式摆姿态。

## 只读检查缺项

```bash
conda activate ros-arm-env
cd /root/jjt/arm_playground
python -B pose_setup.py status
```

## 到达姿态后再记录

在已审核并单次批准的运动操作后，机械臂确实到达准备位置时执行：

```bash
python -B pose_setup.py --real capture ready
```

其他位置依次将ready替换为上表中的名称。脚本打印六个原始读数，验证目标，确认后备份并写入config.json；仅登记参数，不登记路径已验证。若拒绝保存，查看 `logs/pose_samples.jsonl` 中的原始样本。

如果5号关节目标90°、回读89°，起始观察允许该1°偏差，但不能把89°直接存为运动目标。明确核对该姿态的五个实际指令目标后，使用 `--angles` 手工填写五个目标整数；程序不会自动补1°或截断。其他关节也不能依据误差自动修改目标。夹爪记录使用一个目标整数。无需执行任何纠正运动来使回读恰好等于指令。

## 路径验证和视觉

参数齐全后先查看模拟：

```bash
python -B arm.py run --target yellow
```

初次实机路径从已核对的空载起始状态开始，逐段审批验证，不能从任意当前位置直接执行ready。完整空载路径通过后，再放一块积木验证夹取和放置。只有路径确实通过，才在sorting_demo/config.json的verified_paths登记yellow。

看板 http://192.168.137.100:8080 用于设置与固定取物标记一致的ROI、调试黄色HSV阈值，最后勾选视觉已核对。一次只放一块积木，页面生成模拟计划不会驱动机械臂。首次完整搬运成功由人工确认，三次成功后再做十次验收。
