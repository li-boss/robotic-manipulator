# 六关节手动测试

设备文件位于 `/root/jjt/arm_playground`。脚本复用 `arm.py` 校验和控制器；默认模拟，不自动轮流运动、不扫描极限。每次test仅操作指定关节一次，须当次输入y。日志保存本次参数、读数、确认状态和人工观察结果。

## 1 进入环境并先读角度

在SSH终端执行：

```bash
conda activate ros-arm-env
cd /root/jjt/arm_playground
python -B joint_check.py --real read
```

应显示ID 1～6的六个有效角度。若报I2C错误或无效读数，先停止运动测试，保留完整输出，排查控制板供电、连接和设备通信。不执行自动重试、扭矩切换或校准来掩盖读取故障。脚本无需ROS节点。

若只想看程序形式，去掉--real；虚拟读数不能用于配置实际关节。

## 2 填写专用测试配置

打开 `/root/jjt/arm_playground/joint_check_config.json`。新文件所有工作范围为空，hardware_ready为false，未改动原config.json。

`joint_limits`每项为你核对过的整数区间 `[下限, 上限]`；可只填即将测试的关节，其余保持null。当前角度和目标都必须位于该区间。范围需根据设备资料、安装和线缆条件核对，不用整段硬边界自动填充，不把读到一个角度视为已验证整个范围。

| ID | 不可突破的项目硬边界 |
| --- | --- |
| 1、2、3、4、6 | 0～180° |
| 5 | 90～270° |

硬边界不代表任意姿态安全，也不是测试极限的目标。不得为了绕过检查扩大配置；无核对依据时保持null。禁止在带扭矩时强掰关节。确认空载姿态、线缆、实际停止方式和唯一控制来源后，才人工将hardware_ready设为true。

motion_ms默认1500，允许500～10000的整数；settle_ms默认300，允许100～5000的整数。两项都是毫秒，不得设为0。

起始回读允许配置边缘1°观察偏差，例如5号目标90°读回89°时不必扩大配置下限。真实读数原样记录，运动目标仍不得低于90°；不会自动把读数加1°、截断或发送纠正指令。含89°的姿态记录不能直接作为5号运动目标，须人工明确核对目标值。

## 3 一次测试一个关节

```bash
python -B joint_check.py --real test --joint 1
```

输入你为本次核对的绝对目标角度；程序先检查范围、读取六关节，再显示起始角度、目标、运动时间和一次动作。确认路径无碰撞、不会牵拉线缆、已掌握停止方式后输入y；其他输入取消。

第一次选经现场核对、接近当前角度的目标，不预设通用安全步长。六号是夹爪，先移除夹爪内物体和手指，不预设角度增减对应张开还是闭合。观察不动、异响、抖动或碰撞趋势时立即停止后续测试，使用已确认的实际停止方式。

依次把 `--joint 1` 改为2、3、4、5、6。每个关节都重新选择目标、重新确认；不要把六条命令作为无人看守的批量测试执行。未配置的关节会拒绝运动。每次写入后只回读，不根据差值补发纠正；复测或回原位置也要另行运行、确认。

运动结束后输入y=目视正常，n=异常，其他=未确认。软件不会自动宣称舵机正常，也不会自动松爪、返回或复位。Ctrl+C只能停止后续下发，不能撤回已发送指令，不等同硬件急停。

## 4 保存结果

实机日志：`logs/joint_check_real.jsonl`；模拟日志：`logs/joint_check_simulation.jsonl`。同一check_id取最后一条记录，不能按日志行数统计测试次数。读角度与运动记录的operation分别为read和test。

建议记录每个关节的当前角度、目标角度、时间、回读角度、目视结果和异常现象。一次正常运动只验证这一段，不证明整个范围、负载或多关节路径安全。
