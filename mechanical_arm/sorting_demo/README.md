# 颜色积木分拣演示

最新本地版本已增加**无标定纸模型模式**：模型提取相机安装与夹持几何，按冻结原始关节读数投影，人工框选、中心与边方向输入，支持只夹取抬升或完整取放。入口仍为`/manipulation`。相机参数可导入或明确使用标称估计，估计不登记为实测标定；实机仍需空载逐步验证。开发板离线，本轮更新待部署。操作及模拟启动见[无标定纸方案](无标定纸方案与参数来源.md)。下文纸张流程属于保留的原方式。

## 人工指定目标的完整抓放（2026年10月16日）

新增独立页面 `/manipulation`：人工框选、点顶面中心及方向，固定点或图中指定放置位置，模型定位、完整有限路径、三维预览与执行。无需调用颜色或物体识别。旧手动、姿态按钮和pickup_only保留。

说明与接口见 [人工完整抓放说明.md](人工完整抓放说明.md)，实物测量和验收由操作者按 [现场测量与验收清单.md](现场测量与验收清单.md) 完成。未知测量和现场证据保持为空，软件测试通过不等于实机抓放通过。

## 不贴永久标记的引导示教

现增加独立“引导示教”页面模块。以观察画面中的顶面位置与已验证目标建立经验映射，无需填写底座坐标或工具尺寸；不声称精确几何避障。首轮9个样本，每开放单元至少一处独立验证且整轮至少5个位置。操作见 [无标记引导示教说明.md](无标记引导示教说明.md)。

接口：GET `/teaching/status`；POST `/teaching/capture`、`/teaching/samples`、`/teaching/fit`、`/teaching/validation`、`/teaching/preview`。默认示教配置为空，模拟不能保存实机验证。逐步与整批执行均复用原 `/control/execute` 当次确认、去重、锁和审计；ROS2仅计算示教计划。原手动与模型模式保留。数据为独立 `teaching_setup.json`，不迁移或补齐原实测数据。

## 单块黄色木块的自动定位抓放

新增坐标标定、顶面定位、ROS2纯计算规划与完整有限任务确认。一次性准备见 [自动定位配置说明.md](自动定位配置说明.md)。旧固定点演示与手动调试保留；下文关于旧固定点任务没有网页实机执行入口的描述仅适用于旧任务。

设备启动方式：`/root/miniconda3/envs/ros-arm-env/bin/python -B /root/jjt/sorting_demo/start_service.py --enable-real-control --enable-ros-planner`。启动不读取舵机或运动；不带开关时默认模拟。不要在现有服务运行时再次启动。

自动接口：GET `/auto/status`；POST `/auto/settings`、`/auto/capture`、`/auto/anchor`、`/auto/intrinsics`、`/auto/dryrun`、`/auto/preview`、`/auto/result`。所有POST复用同源与CSRF保护。完整执行复用 `/control/execute`，必须携带本次一次性编号及 `confirmed=true`。干运行只生成计划，不获得整批执行授权。

课程URDF固定来源与SHA256记录于 `models/course/provenance.json`。后来补充的六个STL包含相机结构（link4）与夹爪（link5）；课程URDF没有单独定义相机光学坐标系、相机内参与夹持中心。安装几何和静态碰撞包络可以从网格提取，仍需明确光学投影参数和工具坐标。ROS2节点只进行数值逆运动学和保守路径检查；设备未安装MoveIt，本版本使用项目自己的单关节顺序搜索与碰撞计算。硬件命令仍通过原Controller，逐关节等待和回读；失败停止后续步骤。

自动准备数据为 `auto_setup.json`，默认测量值为空、核对标志为假。改变测量数据清除核对状态；改变机械臂配置也使自动任务失效。实机采样保存在 `logs/calibration`，任务日志使用 `logs/events.jsonl`，逐步审计使用原控制日志。没有自动循环或自动失败恢复。

本阶段用于固定点单块有色积木演示，不能作为真实垃圾识别验收。所有机械臂操作遵守项目根目录的 `AGENTS.md` 和 `机械臂操作准则.md`。

## 摄像头与看板

设备文件统一放在 `/root/jjt/sorting_demo`。停止旧预览进程前先确认其PID和命令；两个服务不能同时占用相机或8080端口。

```bash
cd /root/jjt/sorting_demo
/root/miniconda3/envs/ros-arm-env/bin/python -B server.py
```

访问 http://192.168.137.100:8080 。默认模拟，启动不初始化机械臂。若需要页面实机示教，启动时显式添加 `--enable-real-control`；启动仍不读取关节或发送运动。ROI和视觉核对状态初始为空/未确认；HSV默认值是调试起点，不代表现场已验证。

### 页面单关节示教

1. 看清页面“实机 / 模拟”模式，关闭其他机械臂控制程序，点击“读取六关节”。模拟读数不能用于实机配置。
2. 在一个关节的输入框填写整数绝对目标角度，设置运动时间，点击该行“预览”。输入框保持空白，不自动把读数转换成目标。
3. 审阅本次关节、目标、用时、原始起始读数和检查结果，核对现场条件与设备停止方式，勾选后点击“确认执行这一次”。只有这一步会发送单次运动。一次预览120秒有效；改参数后重新预览。
4. 等执行状态完成并现场观察。断网或请求超时不要重复操作，恢复后查询状态；重复请求不会再次下发。网页不是硬件急停，不会撤回已发出的指令。
5. 到达所需位置后，在“保存当前位置”选择名称，明确填写已核对的五个目标或夹爪一个目标，预览并确认保存。读数89°原样记录，5号目标仍必须至少90°；不能自动加1°。保存不运动、不回放，也不标记路径已验证。

夹爪的开合方向和夹持角度须实际验证，不预设。摄像头随机械臂移动，调整后重新核对ROI；抓取时目标可能离开画面，应现场观察夹爪。实机命令和原始读数记录在 `arm_playground/logs/web_control.jsonl`，保存时保留原配置备份。

把积木放在固定取物标记上，从画面确定ROI原图像素坐标，填写左、上、右、下。调试面积和HSV阈值，再勾选已核对。区域内只能有一块互相分离的有色积木；相接目标、灰白/黑色目标和复杂背景不在首版保证范围内。配置区域与真实抓取标记必须由人对齐。

初期颜色到区域只映射 yellow。每增加目标区域，必须先在机械臂配置中记录姿态、验证对应路径，然后再配置映射。不要把颜色映射成通用垃圾类别。

“生成一次模拟计划”验证完整动作参数。未填关节范围或姿态时应显示拒绝；不填虚拟角度冒充实测。有效模拟计划只描述步骤，不执行控制器，也不算实机成功。

接口：GET `/status`、`/stream.mjpg`、`/detection`、`/events`、`/statistics`、`/task-status`、`/settings`、`/control/status`。POST `/control/read`只读，`/control/preview`校验并读取起始姿态，`/control/execute`使用一次性token和明确confirmed=true。控制POST要求同源Origin和状态返回的csrf令牌。POST `/settings`仅修改视觉参数；POST `/simulate`使用当前检测的request_id。分拣任务仍无网页实机执行入口。JSONL任务日志为 `logs/events.jsonl`，按task_id取最新事件统计；损坏行显示计数，程序不删除原日志。

## 实机任务的前置条件

1. 先核对停止方式、六个关节范围、当前空载姿态、线缆余量和单一控制来源。
2. 使用原 `arm_playground/arm.py` 的读取、姿态记录及逐步操作，验证完整空载路径。每次运动都须说明具体关节目标和时间并取得当次确认；读取姿态不证明路径安全。
3. `arm_playground/config.json` 填入实测参数；只有核对后才启用hardware_ready。`sorting_demo/config.json` 的verified_paths只由人工在路径验证后填写，网页不可修改。
4. 程序默认模拟。`run.py --real` 必须由操作者明确启用，并在终端审阅完整计划和逐步批准。运行前重新核对规则、实际源码与参数。不能把本说明当作实机批准。

```bash
cd /root/jjt/sorting_demo
/root/miniconda3/envs/ros-arm-env/bin/python -B run.py
```

实际成功由人观察确认，夹空/掉落选择失败；异常停止后续下发、不自动重试或复位。停止进程无法撤回已发送指令，Ctrl+C不是硬件急停。终端程序与网页使用同一日志；实机启动使用原控制层的硬件锁，该锁不能约束Notebook或其他外部控制程序。
